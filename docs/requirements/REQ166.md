## Description

The application's own colour tokens resolve to the decided direction below in both schemes, replacing the tangerine accent and warm-slate neutrals they carry today. One accent value per scheme, and no arithmetic between them — the light scheme is not a negative of the dark one. In the light scheme elevation runs *toward white*: a card is lighter than the ground it sits on, which is the reverse of today, and depth comes from 1px hairlines plus a one-pixel shadow (`0 1px 2px rgba(9, 9, 11, .05)`) rather than from glow, which stays a dark-scheme device. The accent is rationed to what is interactive, active or measured — bar fill, ring, link, focus ring — while heavy emphasis in the light scheme is carried by the ink `#09090B`, so the primary button is ink on light and remains the glowing accent surface on dark. Everything else about the `Signal` system — the `void → surface → raised` hierarchy, typography, grid, mono metadata, bars, motion — is unchanged. Done when: no user-facing surface resolves to `#ff6b35` or the warm-slate neutrals in either scheme, accent-coloured text measures at least 4.5:1 against the surface behind it in both schemes, and the repo's gate and test task (both named in `AGENTS.md`) stay green.

## Notes

Current behaviour: `src/index.css:11-105` is the whole of it. The `@theme` block holds `--color-accent: #ff6b35` with its `-hover`, `-glow` and `-dim` companions (lines 26-29), the per-scheme `--color-accent-text` pair added by REQ157 (lines 39-40, 81-82, 102-103), the warm-slate neutrals `--color-void: #0a0a0b` through `--color-text-dim` (lines 15-23), and `--color-poll-1: #ff6b35` (line 50) — the first series colour on every result chart, which is the same orange under another name. The `:root.light, :root.auto` override at lines 62-83 sets `--color-void: #ffffff` above `--color-surface: #f1f5f9` above `--color-surface-raised: #e2e8f0`, so elevation there runs *darker* as it rises; that is the direction the table above inverts.

The two roles the table does not name: `--color-surface-hover` has no counterpart in the decided direction, and `--color-poll-1` is a chart series colour rather than a system role. Neither is left resolving to the retired orange.

Measured (WCAG 2.1, accent against Card): light `6.71:1` AA, dark `3.61:1`. The dark value clears the 3:1 that graphics demand, so it carries as button, bar, ring and focus ring, but it is under the 4.5:1 that *text* demands — which is why the done-when states an outcome rather than a value, and why the per-scheme accent-for-text token REQ157 introduced is the seam the outcome is reached through. Affected today are small mono metadata, state chips and the code chip. Text on ground measures 19.06:1 light / 18.10:1 dark, muted on ground 7.89:1 / 7.76:1, label on an accent surface 6.71:1 / 5.13:1.

Not in scope, and why: the `signal` deck theme in `src/components/DeckTheme.tsx:177-223` duplicates today's `index.css` values to the digit under a stated invariant — a deck that never chose a theme must look exactly as it did before themes existed. Whether the *house deck theme* re-skins along with the chrome changes how existing decks render for their audiences, and that is a separate decision with its own requirement; this one covers the application chrome. Also excluded: pulling circular UI elements onto the wordmark's stroke ratio and using an open ring against a closed ring as a run/ended state — proposed alongside this direction but not decided.
