## Description

A guess slide can carry a reference number. It is withheld from non-editors until the presenter reveals it, and then shown against the distribution.

## Updates

- 2026-08-05 — Correct reference number shipped as guessReference on SlideSchema — a nullable GuessReferenceSchema defaulting to null. The modelling decision recorded in schemas.ts: null is not "tolerance zero", it is a slide with no notion of correctness at all, mirroring the stance REQ013 already takes for a choice slide whose author marked no option correct. GuessReferenceSchema.value is deliberately defaultless (ADR-0018) because a defaulted 0 would assert a correct answer nobody authored; guessReferenceFor() is the single resolver so "no correctness" has exactly one shape at every read site. getSlideResults emits reference, tolerance, correctRange, correctCount and correctShare together as explicit nulls when there is no reference (ADR-0024), so a consumer can tell "no right answer" from "nobody was right". The reveal rides the existing REQ102 results-visibility gate rather than a second switch — set the slide to on-click for a deliberate post-vote reveal — which is documented in docs/api.md. Editor: a toggle states the choice, and the reference/tolerance fields stay on screen disabled with the reason spelled out when it is off (ADR-0025) rather than disappearing; a new .input:disabled token in index.css owns that styling once (ADR-0028). The shared screen draws a line through the reference column and reports "Correct answer: 14 (±2 counts — 12-16)". Tests: server/guess.schemas.test.ts (a reference cannot exist without a value; a slide has none until authored), server/guess.integration.test.ts (a slide with no reference reports all five fields null), src/components/GuessDistribution.test.ts (no reference highlights nothing). Verified in the browser: the reference line landed on its own column and the reveal read correctly for 3 guesses.
