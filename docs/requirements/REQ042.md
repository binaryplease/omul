## Description

A guess slide can carry a tolerance around its reference value; answers inside the window count as correct.

## Updates

- 2026-08-05 — Tolerance shipped as guessReference.tolerance — nested *inside* the reference rather than beside it, which is how the dependency is stated in the type: a tolerance without a reference is a window around nothing, and modelling the two as independent fields would have forced a silent tolerance-0 default onto every slide, reading as "only the exact number counts" on slides whose author never made that decision. Inside a present reference the default 0 is a real answer to a real question (REQ042 own example: reference 7 ±0 accepts only 7), and that reasoning is recorded in schemas.ts. correctGuessRangeFor() derives the accepted window once (ADR-0026) — inclusive at both ends, so 7 ±1 accepts 6, 7 and 8 — and is deliberately not clamped to the slide range, since clamping would quietly make a granted window asymmetric. getSlideResults reports correctRange, correctCount, and correctShare as a percentage of the guesses read; correctShare stays null while nobody has guessed, because a percentage of no responses does not exist (the same reading averagePoints takes for an unfunded item, ADR-0024). Editor: a tolerance field beside the reference with a live "12 to 16 counts as correct" / "Only 10 counts as correct" hint. Shared screen: a tolerance band behind the columns, spanning whole columns so its edges land on bar edges, with the accepted guesses drawn green. Tests: server/guess.schemas.test.ts (±0 and ±1 windows, negative/fractional tolerance rejected), server/guess.integration.test.ts (both edges of 6-8 count, 5 and 9 do not; correctShare null with no guesses), src/components/GuessDistribution.test.ts (a column touching either edge is correct). Verified in the browser: with reference 14 ±2 over guesses 4/16/20, the screen read "1 of 3 landed inside it · 33%" and the band covered exactly the 12/14/16 columns.
