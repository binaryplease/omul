## Description

As the operator of an instance that is reachable from the internet so that participants can join, I want to switch off creating presentations without an account with one environment variable, so that a visitor cannot store presentations on my server. A caller with an account, by cookie session or personal API key, keeps creating presentations as today. Joining a presentation by code stays open to everyone without an account, and presentations that already exist keep working, edit tokens included. With the variable unset the instance behaves exactly as it does today.

## Notes

**What happens today**, read at `0249270`. Two server routes write a new deck, and both accept a caller without an account:

- `POST /api/presentations` (`server/routes/presentations.ts:619`) creates a deck for an anonymous caller and returns a one-time `creatorToken`. It spends the create rate-limit budget (`guardCreate`, `:625`) before it resolves the caller (`:645`). A blank deck, a catalog template (`templateId`), a duplicated deck and an imported file all arrive here: `duplicatePresentation` and `importPresentation` (`src/api.ts:1538`, `:1572`) call `createPresentation`, and so does the command-line client (`cli/commands.ts:389`). A create that names a workspace already requires an account (`:647–663`).
- `POST /api/deck-generation` (`server/routes/deck-generation.ts:85`) creates a deck through the same `createPresentation` service (`:132`) and accepts an anonymous caller when the operator set `OMUL_GENERATION_ALLOW_ANONYMOUS=true` (`server/deck-generator.ts:677`, `requiresAccount`). It refuses a signed-out caller with `401` and `refused: "account-required"` before it spends its budget (`:110`).

On the client, the home page offers Create Presentation, Use template, Generate a draft and Import to a signed-out visitor (`src/pages/HomePage.tsx:306–368`) and duplicates a deck from its list (`:263`); `CreatePage` (`:733`) and `TemplatesPage` (`:126`) create on submit, and `GeneratePage` disables itself when `requiresAccount` is true and nobody is signed in (`:107`).

**The variable.** `OMUL_GUEST_CREATION_DISABLED`, parsed by the same rule as REQ251's `OMUL_SIGNUP_DISABLED`: unset or `"false"` keeps creation without an account open, `"true"` closes it, any other value stops the server at boot with an error naming the variable. `.mise.toml` sets the default `"false"`. The two switches are independent; either may be set without the other.

**Server.** While the switch is on, both routes refuse a create without an account with `401` and an `error` message saying this instance creates presentations for signed-in accounts only, and a refused caller spends no rate-limit budget. `GET /api/deck-generation` reports `requiresAccount: true` while the switch is on, whatever `OMUL_GENERATION_ALLOW_ANONYMOUS` says. The command-line client prints the server's `error` field. Existing decks are unaffected: ownerless decks stay editable with their edit token, and claiming one (`POST /api/presentations/:id/claim`, `server/routes/presentations.ts:1265`) requires an account as it does today.

**What the client is told.** `guestCreationOpen` in `GET /api/instance-access`, the endpoint REQ251 introduces; whichever of the two requirements is built first creates it with both fields.

**Client.** Every create surface reaches the same answer from the session and `guestCreationOpen`. While creation is closed and nobody is signed in, the home page's Create Presentation, Use template, Generate a draft, Import and Duplicate controls stay visible and disabled, each stating the reason (sign in to create a presentation) the way `docs/frontend.md` describes for an unavailable control (REQ127). `CreatePage` and `TemplatesPage` disable their create action with the same reason, because both are reachable by URL. Join with code stays enabled.

**Done when** with `OMUL_GUEST_CREATION_DISABLED=true` an anonymous `POST /api/presentations` answers `401`, with and without `templateId`, and spends no rate-limit budget; a create with a cookie session or an API key answers `201`; an anonymous `POST /api/deck-generation` answers `401` even with `OMUL_GENERATION_ALLOW_ANONYMOUS=true`; `GET /api/instance-access` reports `guestCreationOpen: false`; the client's create controls are disabled with their reason for a signed-out visitor; and an invalid value stops the server at boot naming the variable. With the variable unset each of those behaves as before. The route descriptions served at `/api/docs`, `docs/api.md` and `docs/deployment.md` state the switch. The gate and the test suite `AGENTS.md` declares stay green.

**Out of scope.** Restricting which accounts may create: every existing account may create, and REQ251's switch decides who gets an account. Deleting or expiring decks created before the switch was turned on. Any change to the landing page beyond disabling the controls named above.
