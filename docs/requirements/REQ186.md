## Description

As the operator of an omul instance, I want a sample of participants to be asked once, on their own device and after the session has ended, how they found omul. The question must be in omul's own look and plainly addressed to the instance, not to the event's organizer, and the answer must not be traceable to the person or the event. That way I learn from real use at the moment it happened, without putting anything into someone else's deck.

## Notes

**Built on REQ185.**
- **Store:** answers go to the `participant_feedback` table of the feedback database REQ185 introduces (`server/feedback-store.ts`, `OMUL_FEEDBACK_DB`). The columns are those of `user_feedback`, minus `surface` and `contactAccountId`, and the same never-stored list applies with no exception: an account id is never stored here.
- **Form:** the prompt renders REQ185's `FeedbackForm`, so the same rule holds — a rating, a comment or both, at least one; a comment alone is a complete answer. The prompt never draws the "You can contact me about this" checkbox, even for a participant who is signed in. This channel is anonymous by definition. A participant who wants a reply uses the menu form.
- **Operator view:** answers appear under the `participant` channel of `GET /api/admin/feedback` and on the `/admin/feedback` page.
  - The store opens when either switch is on, and the operator view then reads both channels; it answers `404` only while both are off. A per-channel `404` would leave a prompt-only deployment's page on its "not collected" screen, since the page opens on the menu's tab.

**Where it appears, and why there.**
- **Place:** on the participant's ended screen, the `pres.status === "ended"` branch of `src/pages/ParticipantPage.tsx`. The participant reaches that screen when the deck goes to `ended` and `presentation.ended` arrives.
- **Never elsewhere:** it is never a slide or added to a deck, and never appears on the presenter's screen, the shared-results page or an export.
- **Look:** the ended screen is in the deck's theme (REQ079) under the organizer's logo (`DeckMark`, REQ136). The prompt is a separate card in **omul's built-in default theme**, a `DeckThemeScope` with `deck={null}` (the scope the loading screen uses), and it carries omul's own logo (`BrandMark`). Being visibly a different surface is what tells the participant this is not the organizer's question; wording cannot do that alone.
- **What stays:** the organizer's logo, the "presentation ended" heading and the "thank you" stay as they are.

**What it says.**
- The heading names omul as the tool behind the session, e.g. "How did you find omul, the tool behind this session?"
- One sentence says the answer goes to the people who run omul here, not to the event's organizers, and that it is anonymous.
- A dismiss control closes the card. Dismissing counts as being asked.
- All of it is in the deck's language: new keys in the `Dict` of `src/i18n.ts`, filled for all seven languages (`en de fr es it pt nl`), read through `getDict(pres.language)`. The stored `language` is the deck's language.

**Who is asked.** All four must hold:

1. **The prompt is on** for this instance (configuration below).
2. **The device was in the room before the deck ended.** The participant page saw the deck in `draft` or `live` during a visit and recorded that per deck on the device. A device that first opens a deck after it ended is never asked.
3. **The participant is in the sample.** The client hashes `participantId` (`omul-participant-id`, `getParticipantId()` in `src/api.ts`), the presentation id and `sessionStartedAt`, and compares the result with the configured percentage. Because it runs on the client, a reload gives the same answer and the server never learns who was sampled. A deck that ended without going live (`sessionStartedAt` is null) asks nobody.
4. **The device is outside the cooldown.** A timestamp stored on the device records the last time it was asked, whether it answered or dismissed.

**Configuration.** Off on a fresh install. This switch is independent of REQ185's `OMUL_FEEDBACK_ENABLED`, so an operator can run either channel alone.

| Variable                             | Default       | Meaning                                              |
|--------------------------------------|---------------|------------------------------------------------------|
| `OMUL_FEEDBACK_PROMPT_PERCENT`       | unset (= off) | Integer 1–100: share of eligible participants asked  |
| `OMUL_FEEDBACK_PROMPT_COOLDOWN_DAYS` | `30`          | Minimum days before the same device is asked again   |

- A malformed value stops the server at startup with an error naming the variable.
- The client reads both values from `GET /api/feedback/config` (REQ185) as `promptPercent: number | null` and `promptCooldownDays: number`.

**Write path.** `POST /api/feedback/participant` with `{ rating?, comment?, language }`, where `language` is checked against the seven `Lang` values.
- It answers `404` while the prompt is off, for every request — the body is not read or validated first, the rule REQ185's write route follows.
- It takes `application/json` only and refuses any other content type with `415` before validation and before the rate limit, for the reason REQ185 gives.
- It never resolves the session, and the body schema drops anything beyond the three fields, so nothing of the caller can reach the row.
- It is rate-limited by client address under REQ145, with its own rule in `server/rate-limit.ts` sized for a room behind one NAT (Network Address Translation), plus a row in the abuse-limits tables. No per-participant rule applies, because the request carries no participant id.

**Out of scope.**
- Any per-deck, per-account or per-workspace exemption from the prompt. The instance-wide switch is the only control.
- Showing omul's branding anywhere else on participant surfaces.
- Survey-mode decks before they end. Survey mode has no "finished" state of its own (on the last slide the next button is simply disabled), so a survey participant is eligible only once the deck has ended.

**Done when.**
- **Prompt off** (percentage unset): the ended screen renders as it does today, and `POST /api/feedback/participant` answers `404`.
- **Percentage set to `100`:**
  - a participant who joined a live deck sees the card on the ended screen, in the default theme, with omul's logo, in the deck's language;
  - a comment-only, a rating-only and a combined answer are each stored in `participant_feedback`;
  - after answering or dismissing, a reload within the cooldown does not show the card again;
  - a device that opens the deck only after it ended sees no card.
- **Sampling:** the sampling function is pure and tested. It returns the same result for the same inputs, and the share asked converges on the percentage.
- **Docs:** `docs/deployment.md`, `docs/api.md` and `.env.example` document the variables and the endpoint.
- **Gates:** `mise run check` and `mise run test` stay green.
