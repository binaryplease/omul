## Description

As an organizer who builds decks without an account, I want creating a deck to leave the browser console clean, so that a real error is not hidden among refusals the app provoked itself.

A deck created while signed in is the account's from the start, and this browser keeps no copy of its edit token (REQ194). The client learns that ownership by asking `POST /api/presentations/:id/claim` with the fresh token right after the create. Signed out, that claim can only be refused: the server answers `401`, correctly, and the browser logs it as a failed resource load once per new deck.

- **A signed-out create asks no claim.** Before the claim, the client asks Better Auth's `GET /api/auth/get-session`, which answers 200 either way, `null` when nobody is signed in. On `null` the token is kept as the deck's only credential and no claim is sent.
- **Uncertainty keeps the old path.** A failed or unreadable session lookup proves nothing, so the claim is asked exactly as before.
- **Unchanged:** a signed-in create keeps no token (REQ194); `claimLocalPresentations()` on sign-in adopts every locally held deck; the server's claim route and its `401` / `409` answers; a create that mints no token (API key, workspace) asks nothing.

## Notes

Defect, **internal**: Re-Test A, N4, still open in Re-Test D section 4 — one `POST …/claim => 401` for the presenter's deck and one for the second editor's scratch deck, both signed out.

- **Client:** `holdCreatorTokenUnlessOwned()` in `src/api.ts` asks `mayBeSignedIn()` before `claimForAccount()`. That's every create path (`createPresentation`, `generatePresentation`, and import and duplicate through `createPresentation`). `mayBeSignedIn()` is a plain same-origin request rather than `authClient.getSession()`: the Better Auth client resolves its base URL from a browser origin and fails under `bun test`, which is where this module is tested.
- **Cost:** one extra `GET` per create. It answers 200 both signed in and signed out, so nothing is logged.
- **Opening a deck in the editor** asks no claim and never did. The second editor's `401` in Re-Test D came from creating its scratch deck.
- **Server, `cli/`:** not touched.
- **Tests:** `src/api.test.ts`, "keeping the edit token a create returns (REQ194)": an anonymous create and an anonymous generation ask no claim (both fail without the session check), an unreadable session still asks the claim and keeps no token on 200, and the existing signed-in and anonymous token tests hold.
