## Description

A deck can carry an organization's branding — colors, fonts, logo — applied across the presenter, participant and join surfaces, including the ones a participant sees before answering.

## Updates

- 2026-08-10 — Deck-level organization branding shipped, completing the theme layer REQ079/REQ136 started. A deck's theme is now either one of the five built-in ids or 'custom', in which case themeBrand on the deck carries the brand: name, accent, canvas and text as strict #rgb/#rrggbb, plus a font id (REQ092). It rides the ordinary presentation document beside themeLogoUrl/themeLogoAlt, so it reaches every surface the theme already reached through the same <DeckThemeScope> wrapper with no per-surface work — presenter, participant (including the join, waiting and ended screens a participant sees before answering), preview, editor preview pane and shared results. Set through the ordinary owner-or-edit-token PATCH; no new endpoint and no new credential. There is no workspace entity in this codebase, so the deck's theming block is the carrier, exactly as REQ136 already resolved it. Tests: server/theme.schemas.test.ts, server/theme.integration.test.ts (create + PATCH + join round-trip), src/components/DeckTheme.test.ts.
