## Description

A submitted question carries an upvote count and an answered flag. Both are written through the Q&A surface and broadcast to the room; one participant's upvote counts once.

## Updates

- 2026-08-06 — Upvotes and processing status on the Q&A queue: POST /qa/:questionId/upvote toggles (participantId required, no self-upvotes, only on a published list — you cannot vote on what you were not shown), POST /qa/:questionId/answered marks answered and is reversible, behind owner-or-edit-token. rankQAQuestions orders the list open-first, then most upvoted, then longest waiting, with the id as a stable final tie-break; clients render the server's order and never re-sort. Duplicate questions fold into an upvote on a published list only, via normalizeQuestionText now shared with the open-text auto-upvote. Entries carry own/upvoted instead of the asking participant's id.
- 2026-08-07 — Review cleanup (ADR-0025): the Q&A queue button on the presenter screen, whose open-question count orders this requirement's queue, is no longer hidden from a viewer without the edit token — it is disabled with its reason instead, and withholds the count rather than reporting the reader's own questions as the room's. Panel contents and the mark-answered affordance are unchanged.
