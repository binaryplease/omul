## Description

As a participant whose deck has just ended, I want the one control on my last screen to speak the deck's language, like everything before it, and to take me to a home page in that language. Today the screen says "Presentation Ended" and "Thank you" in German for a German deck, then offers an English "Back to home" that opens the app's English-only home page.

The control's label comes from the participant dictionaries (`src/i18n.ts`, REQ084) in all seven languages and stays neutral and navigational ("Go to the omul homepage", "Zur omul-Startseite"). Where it leads is the instance's to configure:

- `OMUL_WEBSITE_HOME_URL_DE` and `OMUL_WEBSITE_HOME_URL_EN` name the product website's German and English home. A German deck links to the German home and a deck in any other language to the English one. When only one is set, every deck links to that one.
- With neither set, which is the default, the control opens the app's own home page as before, with the localized label.

A self-hosted instance is never sent to anyone else's website by default.

## Notes

**Only a link the participant clicks.** Configured, the control is a plain `<a href>` to the address exactly as written. Nothing is appended to it, and nothing navigates on its own: no server or proxy redirect, no `location` assignment, and no reading of `Accept-Language` or `navigator.language`. The deck's language is the only input, and it is the language the screen is already drawn in. An operator should configure each language's canonical address so that the click takes no redirect hop.

**Where it lives.**

- `server/website-links.ts` reads the two variables. A value is an absolute `http(s)://` URL or a path on this host, under the same rule as the legal links (REQ183), now shared in `server/configured-url.ts`. Anything else stops the server at startup with an error naming the variable, and the boot log reports each one (`[website] …`).
- `GET /api/website` (`server/routes/website.ts`) reports `{ homeUrlEn, homeUrlDe }`, each an explicit `null` when unset.
- `src/components/WebsiteHomeLink.tsx` holds the choice of target (`websiteHomeUrlFor`) and the control. `src/pages/ParticipantPage.tsx` mounts it on the ended screen.

**Out of scope.** The in-app home and the presenter UI stay English (REQ183 notes). The app appends no tracking or referral parameter of its own: a query the operator writes into a configured address (`OMUL_WEBSITE_HOME_URL_DE=https://example.org/?campaign=x`) is the operator's and is followed exactly as written, like the rest of the address. The control's `referrerPolicy="origin"` sends the website this origin only, never the `/join/<CODE>` the participant leaves.

## Updates

- 2026-10-16 — Shipped. The ended screen's control is labelled from `goToHomepage` in all seven dictionaries. It links to `OMUL_WEBSITE_HOME_URL_DE` for a German deck and to `OMUL_WEBSITE_HOME_URL_EN` otherwise, falls back to whichever is set, and opens the in-app home while neither is. Both variables are validated at boot and served by `GET /api/website`. Covered by `server/website-links.test.ts` and `src/components/WebsiteHomeLink.test.ts`. Verified in a browser against a local server: a German ended deck renders `<a href="https://omul.app/">Zur omul-Startseite</a>`, a French one links to `https://omul.app/en`, and with the variables unset the German label is a button that opens `/app`.
- 2026-10-16 — The website link carries `referrerPolicy="origin"`, so a website on the same host is sent this origin and not the `/join/<CODE>` the participant leaves. `src/components/WebsiteHomeLink.test.ts` fails without it.
