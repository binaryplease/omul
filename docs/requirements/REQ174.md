## Description

As an operator of any instance of this application, I want every environment variable the server reads and every database file it opens by default to carry the product's own name, so that a self-hoster configuring it reads one product's vocabulary rather than the residue of a working title.

## Notes

Ten operator-facing variables carried the working name — they are now `OMUL_BASE_HOST`, `OMUL_TRUST_PROXY`, `OMUL_RATE_LIMITS_DISABLED`, `OMUL_ADMIN_EMAILS`, `OMUL_ADMIN_DB`, `OMUL_AUTH_DB`, `OMUL_TRUSTED_ORIGINS`, `OMUL_GENERATION_MODEL`, `OMUL_GENERATION_ALLOW_ANONYMOUS`, `OMUL_ALLOW_INSECURE_DEV_AUTH_SECRET` — and the binp-docstore file defaults to `data/omul.sqlite`, the path the container image bakes into its own `ENV`.

**This is a rename and nothing more, because there is nothing to carry across.** The project is greenfield: no instance of it runs anywhere, so no environment is configured under any earlier spelling and no directory holds a database file under one. Every deployment there will ever be is configured from the names documented in `docs/deployment.md` on the day it is first stood up. A compatibility fallback would therefore protect nothing — it would be a second spelling of every variable, permanently readable and permanently owed an explanation, bought against a risk that does not exist.

The first implementation of this requirement shipped exactly that fallback, against a brief that stated the product was live and must not be disturbed. That premise was wrong. The layer it produced — a retired-prefix reader, a startup report naming the old variables, a docstore-filename adoption rule, and the tests holding all three — was withdrawn in full rather than left bypassed, and what is here now is what a rename costs when it is only a rename.

**What survives of the shape, and why it earns its place independently.** `server/store-path.ts` is one reading of `DATABASE_PATH` and one default basename that `db.ts`, `accounts.ts` and `admin-events.ts` all hang off. That was three copies of one descriptor before it (ADR-0026) and it stays one after, for a reason that has nothing to do with naming: three modules deriving a path from the same variable is a descriptor, and a descriptor has one home. Every other consumer reads its variable straight off `process.env` at the point it needs it — there is no wrapper module, because with no fallback to apply a wrapper would only be an alias.

**The one variable that is read under a bracket, and why.** `OMUL_ALLOW_INSECURE_DEV_AUTH_SECRET` is the single switch that permits the development session-signing secret (REQ171), and `server/auth-secret.ts` reads it as `process.env[NAME]` rather than as a dotted literal. `bun build` constant-folds the dotted form for `NODE_ENV`, and this is the one variable whose folded value would be a security posture decided by a build tool (ADR-0036). That is a bundling property, not a naming one, and it stands whatever the variable is called.

Out of scope: the deploy configuration (agenix, compose, Caddy), which lives in a separate private infrastructure repository and is that repository's to change, and the repository and registry names, which are operations rather than source.

**Done when.** No variable, database filename or module in `server/` is named for a retired spelling; the documented `OMUL_*` names are the only ones the server reads; and the repo's gate and test task (both named in `AGENTS.md`) stay green.
