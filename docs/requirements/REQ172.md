## Description

As a stranger who has cloned this repository and holds nothing else, I want a self-contained way to run a production instance — a compose file or equivalent in the tree, an environment-variable example, and a README path that ends at a working deployment — so that the repository is self-sufficient for the audience a published repository actually has, rather than only for a developer on the machine it was written on.

## Notes

Raised by a publication readiness check, **internal**. Nothing here is a disclosure; it is the buildability half of publication readiness, and it is the one that is easy to declare finished because the development path works.

**What exists today.** `README.md` documents exactly one route: `nix develop`, which installs dependencies and starts the dev servers. That route is real and it works. What follows it does not exist in this tree — there is no `docker-compose.yml`, no `compose.yaml`, no `.env.example`, and no production section in the README. The `Dockerfile` builds an image and `.github/workflows/build.yaml` publishes it to the container registry, so the artifact a self-hoster would run is produced; nothing in the repository tells them how to run it, what to set, or what to persist.

**Where the missing half currently lives, and why that is the problem.** The production compose file is delivered by the private infrastructure repository through NixOS `environment.etc` (REQ163, class 1). It is written for one host, it carries that host's topology, and it is not in this tree. So the only complete answer to "how do I run this" is held in a repository a stranger will never have — which is precisely the condition publication is supposed to end. The remedy is not to copy the private file across, which would carry the topology with it, but to write a self-hoster's compose file that owes nothing to that host: the published image, the state volume, the ports, and the environment variables the deployment must supply.

**What the environment example has to name, at minimum.** `BETTER_AUTH_SECRET` (see REQ171, which makes its absence fatal), `OMUL_BASE_HOST` as a bare host, `OMUL_TRUST_PROXY` where a reverse proxy terminates TLS, `DATABASE_PATH` and the fact that `auth.sqlite` and `admin.sqlite` resolve as siblings of it — so a volume mounted at the file rather than the directory loses two of three databases — and the administrator allowlist variable REQ164 introduces. The optional model-provider key is already documented and stays optional.

**Two README statements that do not survive the flip.** The `Public URL` line names the operator's own instance as though it were the project's, and the getting-started path is development-only. A published README's first job is to get a stranger from clone to running instance; the deployment section is that path's second half, not an appendix. Restating the public-URL line is REQ163's class 1 work and is noted here only so the two are not fixed twice in different directions.

**Not in scope.** The Nix development route, which works and stays. The private infrastructure repository's own compose file, which is that repository's business. Whether the project offers a hosted instance at all, which is a business decision and not a code requirement.

**Done when.** A self-hoster's compose file and an environment example ship in the tree; the README carries a production section that runs the published image from a clean machine with no access to any private repository; and a run performed from a fresh clone, following only the README, reaches a working instance.

## Updates

- 2026-08-27 — Filed by a publication readiness check. The development path is verified working; the production path exists only outside this repository. Recorded as a publication blocker under the rule that a stranger must be able to build *and run* the artifact from the public repository alone. No files added.
- 2026-08-28 — The missing production half is not missing everywhere: docker-compose.yml, docker-compose-dev.yaml and .env.example exist in the archived predecessor at commit c73eb72 on task/deployment-readiness-verified, together with a loadtest harness. They are a source to rewrite from and not a file set to copy — that compose file is written against MongoDB, and this product has run on SQLite since the storage layer was replaced, so the services, the volume and the environment table are all wrong in the same direction. The environment example there also predates BETTER_AUTH_SECRET failing closed (REQ171), the deployment-supplied administrator allowlist (REQ164) and OMUL_TRUST_PROXY. One thing in that commit deliberately does not come across: docs/security-papers/ is a set of operator and data-protection documents about a specific hosted service, including its subprocessors — a published code repository is not where they belong, and carrying them over would disclose the operator's processing arrangements to every clone.
