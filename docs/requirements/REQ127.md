## Description

Several slides can be selected and copied, moved, skipped or deleted in one operation, applied atomically.

## Notes

### Slices

- [x] **REQ127/1-select-move-skip-delete** — in the deck editor several slides can be ticked in the rail (a checkbox per thumbnail, Ctrl/Cmd-click to toggle, Shift-click for a range from the cursor) and, from the bar at the head of the slide list, moved one step as a block in their relative order, skipped or included again, or deleted. Each is one editor-document operation (`move-slides`, `set-slides-skipped`, `remove-slides`), so nothing is half applied; a delete covering every slide is refused whole and its control disabled with the reason, and the single-slide cursor always ends on a slide that exists. Persistence stays the existing Save. Built by NST11855-bulk-slide-operations-slice1.
- [x] **REQ127/2-copy-selection** — the selection can be copied in one operation; the duplicates get fresh slide ids and fresh ids for every nested row, and are inserted after the selection. Closes REQ127. Built by NST11858-copy-slide-selection.

**Known limits and follow-up, from the pre-merge review (2026-10-25).** None blocks this record; each is recorded so it is not rediscovered.

- **Wording.** The bulk delete's confirmation reads "The 1 slide you selected leave the deck." for a single slide (`src/components/SlideBulkBar.tsx`); the verb does not follow the count.
- **"Add slide" at the slide limit.** With 200 slides "Add slide" was seen not disabled; not checked further. The bulk actions keep to the limit. To be checked.
- **The focus ring dims with a disabled bulk button**, to about 1.6:1. It is visible enough for WCAG 2.4.7, and 1.4.11 excludes disabled controls.
