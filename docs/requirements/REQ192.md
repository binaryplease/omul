## Description

As a presenter on the presenter screen (`/present/<id>`), I want every button in the top bar to be the same height, so that the bar reads as one consistent row rather than a mix of differently sized controls.

## Notes

**What happens today (defect, reported with a screenshot of an ended deck at a width that shows the inline join-code cluster, so `xl` or wider).** The controls in the top bar's action group (`src/pages/PresenterPage.tsx:881-1222`) are sized by four unrelated rules, and the screenshot shows them at visibly different heights:

- The icon and count chips (join-bar toggle `:895`, participants `:919`, Q&A `:950`, audience `:978`, notes `:998`, comments `:1023`, roster `:1053`, blank `:1081`, results link `:1125`, export `:1140`, reset `:1150`) use `py-1.5 sm:py-2` around their content. Some have a 16px icon alone and some have an icon plus a `text-sm` count, so even these chips differ from one another.
- The app-menu trigger (`src/components/ui/AppMenu.tsx:469`) is a fixed `size-8.5`.
- Preview (`src/components/PreviewLink.tsx:20`), Edit (`:1175`, `:1207`), Start (`:1184`), End (`:1196`) and Restart (`:1216`) use `.btn-secondary`/`.btn-primary`, which pad `0.625rem 1.5rem` (`src/index.css:648-678`). In the screenshot they are the tallest buttons in the row.
- The inline share cluster (`src/components/ShareCluster.tsx:157-185`) is one bordered box whose buttons use `py-2`, and its join code is set in a larger font. In the screenshot it is taller than the chips beside it.

**Desired outcome.** Every bordered or filled control in the presenter top bar renders at the same height, at every viewport width and in every deck state.

**Done when.** In a browser at 360px, 768px, 1280px and 1536px wide, for a deck in each of the draft, live and ended states, every bordered or filled control in the top bar has the same rendered height (`getBoundingClientRect().height`). The share cluster counts as one control, both inline and on its own row. `mise run check` and `mise run test`, as `AGENTS.md` declares them, still pass.

**Out of scope.** The Back link, the status badge, the session clock and the View only marker have no button chrome and are not held to that height. Which controls the bar offers, their order, what each one does, and their `aria-label`/`title` stay as they are.

**Note.** REQ190 and REQ191 rebuilt this bar, and its classes now produce one height per width: 38px from `xl`, 40px below `xl` and 44px below `sm`. A `BAR_GROUP` pill is a `BAR_GROUP_ITEM` (`h-8 max-xl:h-8.5 max-sm:h-9.5`) plus `p-0.5` and border, which add 6px. The Deck trigger and the lifecycle buttons use `BAR_CONTROL_HEIGHT` (`h-9.5 max-xl:h-10 max-sm:h-11`). The app-menu trigger uses `BAR_CONTROL_SIZE` (`xl:size-9.5 max-xl:size-10 max-sm:size-11`). The rendered measurement is in the 2026-10-15 update entry below. The editor top bar (`src/pages/CreatePage.tsx`) was not checked for the same mismatch.
