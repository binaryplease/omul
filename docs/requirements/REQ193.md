## Description

As somebody developing omul in my own fork, I want none of the maintainers' setup — the CLA job, image publishing, the private-copy workflow and its tasks — to run in my fork or to read as instructions to me, so that I can branch, push and open pull requests in my fork without red checks, unwanted registry images or rules that do not apply to me.

## Notes

**What happened before (defect).** GitHub runs a fork's workflows only once its owner enables Actions in it. With Actions enabled:

- `.github/workflows/cla.yaml` ran on every public repository. A fork has no `cla-signatures` branch, so the action failed with a 404 on every pull request inside the fork.
- `.github/workflows/build.yaml` pushed an image to `ghcr.io/<fork owner>/omul` on every push to `main`, `rc`, `workbatch/**` or `task/**`.
- Independent of Actions in the fork: a pull request from a fork to this repository ran `build.yaml` with a read-only token, so its push step was refused and the build check went red.
- `AGENTS.md` stated the private development copy, `rc`, `NO_PUSH` and promotion as general rules, so a coding agent working in a fork read them as instructions, and `mise tasks` listed `publish:gate` and `sync:public-main`.

**Desired outcome.**

- The CLA job runs only when `github.repository` is `binaryplease/omul`. `pull_request_target` runs in the base repository's context, so a pull request from a fork to this repository is still checked.
- `build.yaml` builds the image on every run but logs in and pushes only when the repository owner is `binaryplease` and the event is a push, a tag or a non-draft pull request from a branch of the same repository.
- The maintainer process lives in `docs/maintaining.md`. `AGENTS.md` keeps a short pointer saying it does not apply in a fork, and the `workbatch/*` naming is optional there.
- `publish:gate` and `sync:public-main` carry `hide = true` in `.mise.toml`.

**Done when.** The four points above hold in the tree, and `bun test` plus the bun-only guards (`guard-frontend-conventions`, `guard-cli-standalone`, `guard-publication-residue`, `triage validate`) pass.

**Out of scope.** `test.yaml` is unchanged: it needs only `bun`, uses no secrets, and is useful in a fork.

## Updates

- 2026-10-14 — Shipped: CLA job gated on binaryplease/omul, build pushes only from binaryplease repositories, maintainer process moved to docs/maintaining.md, maintainer mise tasks hidden.
