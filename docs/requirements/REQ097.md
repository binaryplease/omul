## Description

An individual slide, with its current results, can be downloaded as a raster image.

## Notes

No implementation of this requirement exists in the tree. The owner took the earlier one out for a complete rewrite, and the rewrite is not bound by that implementation's decisions. The entries under `## Updates` dated 2026-10-21 and 2026-10-22 record the removed implementation and describe nothing in the current tree.

## Updates

- 2026-10-21 — Shipped: one slide with its current results saves as a 1920x1080 PNG, from the presenter's export dialog (Image of this slide, for the slide on screen) and beside each slide on the results page. Drawn in the browser by src/components/SlideImage.tsx out of the shared screen's own heading and tally renderer (PresenterSlideHeading/PresenterStandingsHeading + ResultsDisplay) in the deck theme, laid out in an offscreen same-origin frame of public/slide-image-frame.html at 1280x720 and rasterized at 1.5x by modern-screenshot (MIT, bundled, lazily loaded). The tally is re-read at download time with the page's own credentials (api.getSlideImageResults, no filtered=include), so the server's tallyVisibleToCaller gate decides what a picture holds; pictures hosted on other origins are taken off the slide before it is drawn and refused by the fetch hook. No server route. Verified end to end in Chromium, WebKit and Firefox, dev and production builds: every slide type with results, private and on-click slides, Greek/Cyrillic/Japanese/Arabic text and KaTeX formulas, an authored brand with slide colours, a 14-option slide fitted to the frame, a phone-width presenter, results-link, stranger, revoked-link and privacy-change races, and an ended deck. Every request an export made went to the deployment itself.
- 2026-10-22 — Review fixes (NST11602): the code, docs and notes no longer claim the rasterizer refuses any other address — its image hook is consulted for pictures alone, and its other requests are for this app's own faces; a test pins that the frame draws no SVG <use>. makeSlideImage now has tests that a withheld or refused read makes no picture and that a content slide is refused before anything is read.
- 2026-11-03 — The owner took the slide image export out for a complete rewrite, so the product offers no way to save a slide as a picture and this requirement is open again. The reported failure of acceptance step T19, given as the reason, was not verified.
