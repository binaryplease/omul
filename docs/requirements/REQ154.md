## Description

The editor's canvas (REQ152) offers a second view: the slide's results as the reveal will draw them, fed by a deterministic sample tally and rendered through the same renderers the live surfaces use (`src/components/Results.tsx`). A Question/Results switch on the canvas frame flips between the two; in the results view the authored chart style, value display and chart colour are shown as the projector will show them, with correct answers marked exactly as the reveal marks them.

Changing the authored chart style or value display from the settings column while in the question view switches the canvas to the results view — the choice is judged against the rendering it selects, not against a labelled card.

## Notes

The sample tally is a thin, deterministic generator per slide type (fixed plausible counts, seeded per slide id — not random, so the preview is stable across renders and sessions). It feeds the existing renderers; no live data, no session, no socket is involved, and nothing about the tally is persisted.

The renderers already accept a tally — this is the same "one rendering path" discipline as REQ152: the editor must be unable to promise a chart the room will not get, because it draws through the room's own code.

Editing is disabled in the results view (the question is read-only there); switching back to the question view resumes in-place editing (REQ153).

Out of scope for this slice: simulating reveal *behaviour* on the canvas — when results appear, countdown flow, hidden-until-reveal states. That belongs to the deferred behaviour-badges iteration; in this slice the reveal setting remains a settings-column concern (REQ155).
