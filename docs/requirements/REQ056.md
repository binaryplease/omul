## Description

Quiz answers are scored against the slide's authored solution without presenter intervention, and the per-participant totals accumulate across the deck.

## Updates

- 2026-08-06 — Automatic scoring shipped. The organizer's existing correct-answer marking (REQ013) now awards points with no manual rework: scores are derived from the votes and the slide as it stands now — never stored — so re-marking a mis-marked solution re-scores the room with no migration. A quiz slide's results payload gains an anonymous 'scoring' block (answeredCount / correctCount / totalPoints / averagePoints / correctShare, plus the window), deliberately naming nobody because the results endpoint is public and a participantId is the only credential a vote carries; a plain multiple-choice slide emits scoring: null (ADR-0024). New GET /api/presentations/:id/scorecard?participantId= serves one participant their own per-slide result and deck totals — the basis REQ059's leaderboard needs. Full docs in docs/api.md.
- 2026-08-07 — Defect found in review and fixed under REQ147: the results payload counted two different units at once — respondentCount counted distinct participants while scoring.answeredCount, correctShare, totalVotes and the per-option counts counted rows, so a participant holding two answers produced a payload reading respondentCount 1 beside answeredCount 2 and a correctShare of 50% on a question one person got right. Every count on a quiz slide now goes through one finalQuizAnswers judgement (standing, and one row per participant, the first), so the scoring block, the option bars, the typed-answer groups, the leaderboard and the scorecard all report the same room.
