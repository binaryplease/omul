## Description

A theme carries the font family its text renders in, loaded so every surface resolves the same face.

## Updates

- 2026-08-10 — A theme now names the face its text renders in, as an id from a closed set this build ships — DECK_FONT_IDS (sora, system, serif, mono) in server/schemas.ts, with the stacks in DECK_FONT_STACKS beside the palettes on the client (ADR-0032). An id rather than a family string is what makes 'every surface resolves the same face' true: Sora and DM Mono are bundled through @fontsource, the other two are generic stacks every system resolves, and ADR-0016 forbids fetching one at runtime, so a theme cannot name a face that renders as the fallback on every machine but the designer's. Both kinds of theme pick from the one set — the five built-ins carry a font id instead of restating a family per colour scheme, and an authored theme picks from the same list in the editor — so they cannot disagree about what 'the serif one' is. deckFontIdFor() is the single read site and resolves an unknown family to the house face everywhere at once; deckThemeStyle() writes --font-display/--font-mono once per scope and re-declares font-family, since index.css resolves the display face on <html>. Tests: server/theme.schemas.test.ts, src/components/DeckTheme.test.ts.
- 2026-09-02 — The house face this requirement's closed set is built around moved from Sora to Figtree (REQ178). The mechanism is unchanged and is the reason the move was cheap: a theme still names an *id* from DECK_FONT_IDS, still four of them — one bundled house face plus system/serif/mono — with the stacks in DECK_FONT_STACKS on the client and deckFontIdFor() still the single read site. What changed is which family the house id names ("Figtree Variable" via @fontsource-variable/figtree) and the id itself (sora → figtree). The closed set is what made the rename a schema question rather than a CSS one: a stored id is gated on every read, so the retired id is folded onto its replacement inside the field's schema (RETIRED_DECK_FONT_IDS, DeckFontFieldSchema) rather than deleted, and a deck written before the move opens, renders in the house face and shows a valid selection in the picker. DM Mono is untouched. Status stays done — this requirement's claim was already true and is still true; REQ178 carries the swap.
