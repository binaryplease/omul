## Description

Whether a slide accepts submissions is presenter-controlled state. A submission to a closed slide is refused with a stated reason rather than silently discarded.

## Updates

- 2026-08-13 — Shipped. Participation is server-managed per-slide live state: closedSlideIds on the presentation (public, defaulted [] so every existing deck reads forward as open), moved by POST /presentations/:id/participation {slideId, open} under owner-or-edit-token, broadcast as slide.participation. slideAcceptsSubmissions/withSlideParticipation in server/schemas.ts are the single reading, composed by the boundary, the shared screen, the phone and the session store. A submission to a closed slide is refused at the boundary on every slide type with a stated reason — VoteRefusal gains participation-closed, answered 400 'The presenter has closed this slide to submissions' on both /vote and /response-vote — rather than silently discarded. Nothing collected is touched: closing keeps every answer and its tally, reopening collects alongside them. Presenter control sits on the slide beside the reveal and the timer (ADR-0031); the phone draws the reason and a native fieldset gate. Reset clears the closed set with the votes; the deck PATCH cannot write it.
- 2026-08-14 — Review fix (NST9011, finding 2): the participation switch lived only on PresenterSlideView, so while the shared screen was blanked (REQ109) the presenter could not close or reopen the slide without first putting the question back in front of the room. It now rides the blanked screen's control slot alongside paging — controls name what they do, never what the deck says — so the two switches stay independent at the control surface as well as in state.
- 2026-08-14 — Review fixes: stated refusals now carry a machine-readable 'refused' code (VOTE_REFUSAL_CODES in server/schemas.ts) beside the English prose, and the participant surface maps the code onto the deck's language instead of guessing the reason from local countdown state — a closed-slide refusal racing the broadcast no longer reads as a quiz lock on quiz slides. setSlideParticipation's read-modify-write on closedSlideIds is serialized per deck (slideListLock, server/keyed-lock.ts), so two concurrent closes can no longer lose one update while both broadcasts go out; concurrency test added in live-room.integration.test.ts.
