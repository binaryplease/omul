## Description

As a presenter on the presenter screen (`/present/<id>`), I want every control in the top bar visible and the Back link never covered, at any window width from a phone to a wide desktop, so that I can reach each action without scrolling the bar sideways and always find my way back.

## Notes

**What happens today (defect, reported with a screenshot of a desktop window wide enough for the inline join-code cluster, so at least the `xl` breakpoint of 1280px).** The top bar in `src/pages/PresenterPage.tsx:856-1235` is one row that never wraps: `overflow-x-auto whitespace-nowrap` (`:860`), a choice its own comment states (`:858-859`, "scrolls horizontally on narrow viewports rather than wrapping the controls"). The left group — Back link, deck title, status badge, session clock — is `min-w-0 flex-shrink` (`:861`), while the action group is `flex-shrink-0` (`:881`) and holds the join-bar toggle, the share cluster (join code, Link, QR, Embed, Edit Link, `:910-915`), participant count, Q&A, audience, notes, comments, roster, blank screen, the app menu (`:1089`), Preview (`:1096`), results link, export, reset, Edit and the lifecycle button (Start/End/Restart). In the reported screenshot the bar scrolls sideways, the deck title is not visible at all, the Back chevron is clipped at the left edge, and the lifecycle button is cut off at the right edge. The code already records the pressure: the comment at `:1112` says the row "already fills a laptop's width". Below `xl` the share cluster moves to a second row (`:1230`), but every other control still shares one non-wrapping row, so on a phone most of them sit off-screen.

**Desired outcome.** At every viewport width from 360px up, the presenter top bar presents every control it offers today without a horizontal scrollbar, with the Back link, the deck title and the lifecycle button visible and uncovered.

**Done when.** In a browser at 360px, 768px, 1280px and 1536px wide, for a deck in each of the draft, live and ended states, the top bar has no horizontal scroll, the Back link, the deck title and the lifecycle button are visible and clickable, and every other control is reachable with at most one extra tap; `mise run check` and `mise run test`, as `AGENTS.md` declares them, apply unchanged.

**Out of scope.** No control is removed, and what each control does, its disabled-with-reason state for a viewer without edit access, and its `aria-label`/`title` stay as they are; only how the bar presents them is in question. The editor (`src/pages/CreatePage.tsx`) and the participant screen have top bars of their own and are not part of this requirement.

**Note.** The request came with a general wish to rework the UI/UX; this record covers only the presenter top bar. The slide rail below it (`src/pages/PresenterPage.tsx:1279`) also scrolls horizontally below `md`, which a later record would have to take up.
