## Description

As a keyboard or screen-reader user, I want every dialog and popover in the product to behave the same way, so that I am never left with focus behind something that is still up. Escape closes it. Focus moves into it when it opens and goes back to the control that opened it when it closes. Tab stays inside a modal dialog while it is up. A popover fits inside the viewport.

## Notes

**Why this record exists.** The pre-merge browser run of 2026-10-25 found the same class of fault on five surfaces, all from main. A requirement that closed one of them would leave the rest, so they share one home here instead of five scattered notes:

- **`Modal.tsx`** (`src/components/ui/Modal.tsx`): the "Export…" and "Share results…" dialogs do not close on Escape, and focus stays on the page behind them.
- **`ConfirmModal`** (`src/components/ui/ConfirmModal.tsx`), for example "Delete N slides?" from the editor's bulk bar (REQ127): no dialog role, no focus moved into it, no Escape.
- **The presenter's QR dialog** (`src/pages/PresenterPage.tsx`, "Scan to join", REQ191): Tab from "Close" leaves the dialog. Any key closes it and gives focus back, so Tab does not strand anybody, but the dialog does not hold focus either.
- **The Reset dialog** on the presenter screen: it does not close on Escape, and Cancel leaves focus on `body`.
- **The editor's "Change slide type" menu** (`src/components/SlideEditor.tsx`): it runs out of the viewport on the right (`left-0 w-80` from its anchor), and it closes neither on Escape nor on a click beside it.

**Done when.** Each surface above, and any dialog or popover added since, meets all four parts of the contract in a keyboard-only run at 390 and 1440px. Shared behaviour lives in one place that the dialogs compose, rather than being re-implemented per dialog (ADR-0026). A test pins the contract for the shared piece.

**Out of scope.** Menus that already meet the contract through `BarMenu` and `useCloseOnEscape` (REQ190, REQ199), and the phone's panel sheet (REQ199), which is not a dialog.
