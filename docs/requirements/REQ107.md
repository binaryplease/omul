## Description

A slide type rendering a countdown of a configured length, started, paused, resumed and reset by the presenter and shown to the room in step.

## Notes

### Slices

- [x] **REQ107/1-countdown-slide-type** — an author can add a countdown slide and set its length; every surface that draws a slide (editor canvas, rail thumbnail, presenter view, participant view, results view, PDF export) draws it at its full length, not running. Built by NST11804-countdown-slide-type.
- [x] **REQ107/2-presenter-run-countdown** — the presenter starts and stops the countdown; the server records the run state and broadcasts it; presenter and participant surfaces draw it running in step against the server's clock, the way REQ057's quiz countdown does. Closes REQ107. Built by NST11807-req107-presenter-countdown.
- [x] **REQ107/3-pause-and-reset** — the presenter pauses and resumes a running clock, and a separate reset returns one slide's clock to its full length; the frozen time reaches every phone by broadcast and on a late join, a finished clock stays at 0:00 until reset, and retried requests change nothing.

### The slide type (slice 1)

- **Type:** `"countdown"` in `SlideTypeEnum`, listed in `CONTENT_SLIDE_TYPES` — it asks nothing, collects nothing and has no aggregate (`slideHasResults` is false), so presenter and participant route it to `ContentSlideView`, and its heading (`question`) is optional like every content slide's.
- **Field:** `countdownSeconds` on `SlideSchema` — whole seconds, `.int().min(1).max(3600).default(60)` (`COUNTDOWN_DEFAULT_SECONDS`, `COUNTDOWN_MAX_SECONDS`). Read it through `countdownSecondsFor` (clamps a hand-built value into 1…3600, missing → 60) and spell it with `formatCountdown` (`m:ss`, minutes unpadded — `0:45`, `1:00`, `60:00`).
- **Face:** `src/components/CountdownFace.tsx` draws a number of seconds as the clock (`role="timer"`); `ContentSlideView` hands it the authored length. Slice 2 hands the same face the time remaining.
- **Editor:** the settings column's "Countdown" group authors the length as minutes and seconds, written through `countdownSecondsFor`; `newSlide("countdown")` and a type change seed 60.
- **For slice 2:** no run state exists yet — no start instant, running flag, route or WebSocket event. Like `revealedSlideIds` and `slideStartedAt`, it belongs on the presentation as server-managed live state, not on the authored slide.

### The run (slices 2 and 3)

- **State:** `countdownRuns` on the presentation (`PresentationSchema` and `StoredPresentationSchema`, `.default({})`) — a `CountdownRunSchema` entry per slide id, `{ remainingMs, resumedAt }`: the milliseconds left when the clock last moved, and the server's instant it set off from them. `resumedAt: null` is a clock frozen at `remainingMs`; no entry is a clock at full length, not running. Server-managed live state beside `slideStartedAt`: absent from `UpdatePresentationSchema`, so the deck PATCH cannot write it, and cleared by a deck-wide reset, paused clocks included. Moved only through `withCountdownRun` (server write and client reducer alike). A run does not read the authored length after it starts, so an edit to `countdownSeconds` moves neither a run in progress nor a finished clock.
- **Phases:** `countdownPhase(run, now)` — `idle`, `running`, `paused` or `finished`. A run with no time left is finished, with no write and no event at the moment it reaches zero.
- **Route:** `POST /api/presentations/:id/countdown` with `{ slideId, action }` (both required; `action` is `CountdownActionEnum`: `start`, `pause`, `reset`), behind `requireEdit` — owner, edit token or `edit` grant. `nextCountdownRun` in `server/schemas.ts` is the state machine: `start` runs an idle clock from full length and continues a paused one from its frozen time; `pause` freezes a running clock at the time left on the server's clock; `reset` removes the run from any state. Every other pairing returns the run unchanged, and `applyCountdownAction` in `server/services/presentations.ts` then writes and broadcasts nothing, so a retried request cannot move a clock and a finished clock leaves only by `reset`. Clients never send a time. Unknown slide → `404`, non-countdown slide → `400`.
- **Event:** `slide.countdown` with `{ presentationId, slideId, run }`, `run: null` after a reset; applied by `applyCountdown` in `src/store/session.ts`. A late join reads the same run from the deck and from `room.joined`.
- **Clock:** `countdownRemainingSeconds(slide, run, now)` in `server/schemas.ts` — full length with no run, the frozen time while paused, else time left rounded up and floored at 0. `now` is the server's clock via `serverNow` (REQ057's offset), so a mid-run join or reload draws the time left. `src/components/CountdownFace.tsx` holds the descriptor (`countdownRunFor`), the ticking hook (`useCountdownSeconds`), the wrapper (`CountdownSlideFace`) and the presenter's `CountdownRunControls`, drawn under the clock. Start/pause/resume is disabled with its reason before the deck is live, on a finished clock or for a spectator; Reset is disabled with its reason on an idle clock or for a spectator, and stays enabled on a deck that is not live, so a clock left paused after End can be cleared. Only the presenter and participant surfaces hand `ContentSlideView` a run; the editor, rail, results view, dry run and PDF draw the full length. `PreviewPage` empties `countdownRuns` on its throw-away deck, because the deck it loads can hold runs from a live session.

**Known limits and follow-up, from the pre-merge review (2026-10-25).** None blocks this record; each is recorded so it is not rediscovered.

- **Typing into the length is fiddly.** Clearing the minutes field reads as zero minutes, so at 5:00 the clamp to one second turns the seconds to 1; typing 45 into an emptied seconds field shows `045`. The stored length is always what the clamp says and can be typed correctly, so this is input friction, not a wrong value. Follow-up: let a field be empty while it is being typed into.
