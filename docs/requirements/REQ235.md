## Description

As a participant using a screen reader, I want a quiz question that has just started to go from "waiting for this question to start" straight to running, so that I am not told for an instant that the time is over on a question that has just opened.

The countdown (`useQuizCountdown`, REQ057) holds the last reading of the clock and re-reads it in an effect, after the render. When the deadline changed, the first render after the change still held the reading taken against the old deadline. Before a question opens there is no deadline, and that reading is zero. Against the new deadline, zero rendered as expired: the countdown said "Time's up" and the answer status line (REQ221) said "The time for this question is over", for the 0–3 ms until the effect ran. Both are polite live regions, and the status line's text is announced.

- **A reading counts only for the deadline it was taken against.** A changed deadline is read from the clock in the render that first sees it. This covers every way a question starts: arriving on the slide, "Start timer" on a question that waited at go-live (REQ226), and "Restart timer".
- **Unchanged:** the interval, its tick and where it stops; the window itself, which stays the server's; the shared screen, which reads the same countdown and so loses the same flash.

## Notes

Defect, **internal**: reported in Re-Test B (N4), still present in Re-Test D at every question start (for example 10:43:07.438 → .440 and 10:59:21.068 → .070), and listed as left open in REQ232.

- **Client:** `src/components/QuizTimer.tsx`. The hook holds `{ deadline, remainingMs }` and derives what it returns through `quizCountdownFrom`, a pure function that uses the held reading only when its deadline is the current one.
- **Tests:** `src/components/QuizTimer.test.ts`, "quizCountdownFrom, the instant a question starts (REQ235)". A reading held from the waiting question, and one that ran out on the old deadline of a restart, are both read as running against the new deadline. A reading taken against the current deadline is used as held. A source guard pins the hook to that function. The tests fail on the tree before the change, which has no such function and derives the countdown from the stale reading inside the hook. The repository has no DOM renderer for tests, so the re-render itself was checked in Chromium, not by a unit test: with a polite-region observer on a German deck's participant page, "Start timer" logged "Die Zeit für diese Frage ist vorbei" for 1 ms on the tree before the change, and no such entry after it, on "Start timer" or on arrival.
