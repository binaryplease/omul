## Description

Slide and question text can carry mathematical notation and render it on every surface, including the participant's device.

## Notes

Defaults chosen where the description left the question open:

- **Notation.** TeX between `$…$` (inline) and `$$…$$` (display). The delimiters follow Pandoc's rules, so prose with prices in it stays prose: an inline formula opens onto a non-space, closes just after a non-space, is not followed by a digit, and stays on its line — `$5 or $10`, `$5-$10` and `5$` remain text. A display formula may pad itself with spaces and run over lines, though not across a blank one; an empty `$$ $$` is text. Inside a formula a backslash belongs to TeX (`\$` is a dollar sign in the formula); outside one, `\$` writes a literal dollar sign. Code spans win over formulas (`` `$HOME` ``), a pasted address keeps its dollar signs, and emphasis steps over a formula rather than closing inside it (`_the root $x_1$_`). A `$$` that opens a line and closes at the end of a line, with no blank line between, is a display block whose lines are TeX, not markdown — `+ b` continuing an equation is not a list item. Text without delimiters renders exactly as it did; on text with no dollar sign the emphasis parser closes where it always has. Existing text with a `$…$` pair whose closing `$` follows a non-space renders as math after this change (`From $5 to infinity$`); there is no migration, and `\$` keeps a literal dollar. Common price text stays text (`From $5 to $10`, `$5-$10`, `US$5`).
- **Surfaces.** Everything that draws authored text through `SlideText`: the presenter's projected view, the participant's device, the editor (on the canvas a heading containing a formula rests typeset and shows its TeX only while it is being typed into; bodies, the canvas's results view and the dry run render as the room does), the results surfaces and presenter notes. Gists — rail rows, thumbnails, `title` and `alt` text — show the TeX without its delimiters.
- **Library.** KaTeX, installed from npm and bundled. Its code is a chunk of its own, fetched from the deployment the first time a formula is on screen, so a deck without formulas costs a participant's phone nothing; its stylesheet is imported by `src/index.css`, and its fonts (OFL-1.1, see NOTICE.md section 3) are emitted by the build and downloaded only when a formula needs them. No CDN, no third-party fetch.
- **Failure.** Malformed TeX, a command KaTeX refuses, or a chunk that fails to arrive shows the formula exactly as typed — never a broken slide. KaTeX draws a refused command in its error colour instead of throwing, so that colour is set to a value no author can write (`var(--slide-math-refused)`) and its presence after rendering is what sends the formula back to its source.
- **Security.** KaTeX runs with `trust: false` — no `\href`, `\url`, `\includegraphics` or `\htmlClass`/`\htmlId`/`\htmlStyle`/`\htmlData`, and no trust hook — plus `throwOnError: true`, `strict: "ignore"`, author sizes held within 10em either way, macro expansion capped at 1000, and a fresh macro table per formula, so a `\gdef` dies with the formula it is in. KaTeX's `maxSize` clamps a positive size past 10em but does not reach a negative one (`\raisebox{-99999em}`, `\rule[-1000em]`, `\kern-5000em`, a `\\[-9999em]` row gap) nor the `\arraystretch` multiplier, so `slideMathWithinBounds` walks the parsed formula — its macros expanded — and refuses one whose size reaches below -10em or whose row stretch passes 3 before anything is drawn (the bound holds for each size, not for their sum: nested `\raisebox{-10em}` add up, as 5,000 line breaks in a text field already can); it is shown as typed. That walk uses KaTeX's own parse, which its authors mark unstable, so it fails closed and `SlideMath.test.ts` pins it. A formula is built by KaTeX's own `render()` from DOM nodes into an element React leaves empty; no HTML string reaches the DOM. `mise run check` refuses KaTeX outside `src/components/SlideMath.tsx` and any raw HTML sink anywhere in `src/`.
- **Phones.** A display formula wider than the screen scrolls sideways in a frame of its own instead of widening the slide's column past the screen's edge.
- **Not here.** The PDF and spreadsheet exports keep showing the TeX source (a follow-up; the PDF's markdown reduction can also drop underscores inside it). Option labels, statements and other answer texts take no markup — formulas included — as they take no markdown. No visual equation editor, and no notation in what participants submit. The results' "Break these results down by" picker is a native `<select>`, which cannot typeset, so a question with a formula shows its TeX source there — the same class as the exports.

The hidden typeset copy of a canvas heading is inert, so a link in it is not a Tab stop, and the raw-HTML guard also refuses innerHTML +=, bracket access and setHTMLUnsafe/parseHTMLUnsafe.
- 2026-10-26 — Fix (F18 from the local pre-acceptance check): moving from a slide with an inline formula to one with a display formula left the previous slide's inline formula on screen in the editor, on the shared screen and on every phone until a reload. The same SlideMath instance turned from inline to display, and both shapes were an unkeyed <span>, so React kept the inline host as the display frame and never removed the nodes KaTeX had drawn into it. The two shapes are now keyed apart, so React replaces the element; SlideMath.test.ts asserts an inline and a display formula are never the same element to React. Status stays done.
