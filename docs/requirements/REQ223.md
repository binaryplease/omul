## Description

As a participant, I want an option I can no longer pick to stay as it is when the pointer is over it, so that a locked card never looks like my answer. This repairs REQ054 (the quiz question's option cards), whose cards kept the accent border on hover after the answer locked.

`.option-card:hover` applies only to a card that is neither `:disabled` nor `[aria-disabled="true"]`. A card that is unavailable shows the `not-allowed` cursor.

## Notes

Defect, **internal**: found by a UI test pass of the quiz feature on `f3bd62e` (polish p1). After an answer was sent the layout shifted under the pointer, and the card it landed on (Mars or Earth, in Chromium and WebKit) took the blue accent border, which reads almost like "selected".

The rule lives in `src/index.css`, the one owner of the option card's interaction states. `ParticipantSlideView.test.ts` reads it and checks that every `.option-card:hover` rule carries the `:not(:disabled, [aria-disabled="true"])` guard.

## Updates

- 2026-10-30 — Shipped. Verified in Chromium: with the answer locked, hovering Venus left border rgb(231,231,234), background rgb(244,244,245) and cursor not-allowed, identical to the resting Earth card.
- 2026-10-30 — Review follow-up: the hover guard sits in :where() so it adds no specificity; a selected card under the pointer (a phone keeps hover after a tap) wears .selected again rather than the hover background.
