## Description

A deck can be opened in a preview rendering the presenter and participant surfaces without creating a session, minting a join code or storing answers.

## Updates

- 2026-08-06 — Preview mode shipped: GET /api/presentations/:id/preview (owner-or-edit-token) returns a dry run of the whole deck, every slide twice — presenterResults as the shared screen reads the tally and audienceResults as a phone reads it (quiz keys withheld, REQ056) — computed by the live aggregation over an in-memory results source against a preview deck state that is built and discarded. New /preview/:id page draws both perspectives side by side with a local slide rail, local REQ102 reveal and a working participant control; entered from the editor and the presenter screen via the shared PreviewLink. The presenter's and participant's slide bodies were extracted into PresenterSlideView / ParticipantSlideView so the preview wears the same renderings the live pages do (ADR-0026/0027). Every slide type in the catalog renders in both panes, guarded by presenterSlideKind/participantSlideKind over the schema's slide-type enum.
