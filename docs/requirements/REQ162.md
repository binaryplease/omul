## Description

As the person who will hold this project publicly, I want `SECURITY.md` naming a live reporting path, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, and issue and pull-request templates in place *before* the repository becomes public, so that the obligations publication creates — vulnerability reports, issues, a name in other people's dependency graphs — land somewhere that exists rather than in a tracker nobody is watching.

## Notes

Raised by a publication readiness check, **internal**.

**What exists today** (re-measured 2026-09-02; the filing state of 2026-08-25 was `README.md` alone at `health_percentage: 28`). All five files are in the tree and on the default branch: `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `.github/ISSUE_TEMPLATE/` (three files) and `.github/PULL_REQUEST_TEMPLATE.md`. `gh api repos/<this remote>/community/profile` returns `health_percentage: 100` with the licence detected as `agpl-3.0`. What is still owed is the CLA: no text in the tree and no enforcing pull-request check. The issue tracker and the pull-request list are both empty, and the wiki — `has_wiki: true` on the repository — has never been initialised, so no `<repo>.wiki.git` exists to sweep. That is a small mercy and not a design: the wiki is enabled and will accept content the moment anyone writes to it.

**Why these are preconditions rather than follow-ups.** A public repository with no `SECURITY.md` receives its first vulnerability report as a public issue, which is a disclosure the project performs on itself. The private-vulnerability-reporting setting that gives a reporter a non-public channel only exists once the repository is public, so the file that points at it has to be in the tree at the moment of the flip, not added afterwards.

**The reporting path has to be real and monitored.** A `SECURITY.md` naming an address nobody reads is worse than none, because it converts a reporter who would have found another route into one who believes they have already reported. Name the address, the expected response window, and the supported versions.

**What the README still owes a stranger.** The current README is good on the happy path — `nix develop` and the dev servers come up — and it is honest about the one optional external service. As of 2026-09-02 it states the license (REQ161) and links the reporting path, so what is left of this paragraph is the part no file can settle: it has not been verified from a fresh clone in a clean environment with no credentials, which is the only test that counts.

**Scope note.** `README.md`, `AGENTS.md`, the design document, `docs/` and `task/` are all excluded from the Docker build by `.dockerignore` but are all part of the published tree — the publication surface is the repository, not the image.

**Contribution terms are decided: a CLA.** The owner has settled this one ahead of the license question, and it is recorded here because it binds independently of whichever license is eventually chosen. A **contributor license agreement (CLA)** is an agreement in which a contributor either assigns copyright in their contribution to the project owner or grants the owner a broad, sublicensable and relicensable right to it. The alternative that was on the table — a **developer certificate of origin (DCO)**, a per-commit sign-off asserting the contributor had the right to submit the code — establishes provenance but grants nothing, and so is not a substitute here.

What a CLA buys, and why the timing is not negotiable: the owner keeps the ability to relicense the project later, and to grant terms to a paying third party that the public license withholds. Both require holding the copyright in every line. A contribution that lands from an outside author without an agreement is owned by that author on whatever terms the public license grants, and there is no retroactive fix short of asking each contributor individually or removing the code. So the mechanism has to be in place before the repository can accept its first outside pull request — which, since a public repository can receive one within minutes, means before the flip.

This is not a claim that any particular license will be chosen. It is the precondition that keeps the choice open.

Three parts, all in the tree: the CLA text itself; an automated check that blocks an unsigned pull request (`cla-assistant` is the common one); and the requirement stated in `CONTRIBUTING.md` so a contributor meets it before writing code rather than after. Grafana is the closest reference — it runs a CLA and says so in its own `CONTRIBUTING.md`.

**Done when.** `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `.github/ISSUE_TEMPLATE/` and `.github/pull_request_template.md` present; a CLA text in the tree with an enforcing check on pull requests and the requirement stated in `CONTRIBUTING.md`; the README states the license and links the reporting path; the community profile reports each file found; and the reporting address has an owner who has agreed to watch it.
