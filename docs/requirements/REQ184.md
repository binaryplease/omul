## Description

As a maintainer of this repository, I want every field a stored slide carries to declare its default or to be identity or creation-time input, so that the declared-defaults rule holds at every depth of a stored document and not only at its top level.

## Notes

**Where this comes from.** `@binaryplease/zodstore` 0.5.0 made its declared-defaults walk recurse: a parent's `.default(...)` does not cover its members, because a row that already stores the object is parsed against every one of them. `server/db.ts` opts out of the library's walk for a reason unrelated to nesting (the foreign keys are plain UUID strings that `ref()` cannot express — REQ177), and `server/stored-defaults.test.ts` enforces the rule in its place. On 2026-10-02 that test was taught to recurse the same way. Its paths match the library's walk exactly. It found 28 bare paths under `slides[]` in `presentations` and `workspaceTemplates`. Twenty-six are identity (each row's `id`) or creation-time input (`type`, `question`, a row's `text` or `label`, a scale label's `value`, a guess reference's `value`, a pin area's coordinates) and are exempt on their merits. **Two are not**, and they are what this requirement is about:

- **`MultipleChoiceOptionSchema.isCorrect`** is `z.boolean().optional()`. `undefined` means "the author never marked this option", and the results export reports it as `null` rather than `false` (`server/results-export.ts`). The audience payload withholds the answer key by dropping the key, so a withheld mark looks the same as an unmarked option (REQ056).
- **`SlideSchema.maxResponses`** is `z.number().int().min(0).max(50).optional()`. `undefined` means "fall back to the legacy `allowMultiple` flag" (REQ022, REQ026).

Both carry a meaning in their absence that no default declares, which is the state ADR-0029 forbids. A plain `.default(false)` or `.default(1)` would erase that meaning: an unmarked option would export as `false`, and an unconfigured slide would stop following `allowMultiple`. The shape ADR-0029 names for a genuinely absent value is `.nullable().default(null)`. Taking it changes each field's type from `T | undefined` to `T | null`, and the read sites on both server and client move with it (about 75 for `isCorrect`, 25 for `maxResponses`, counted on 2026-10-02). That change was not folded into the dependency bump that surfaced it.

The two paths were listed in `server/stored-defaults.test.ts` as `SLIDE_OPEN_DEFAULT_GAPS`, so the recursive walk stayed on for everything else while they were open. The test's "exempt fields carry no default" case fails on an entry that has gained a default, so closing a gap forced its entry out of the list. As of 2026-10-23 both are closed and the list is gone: every bare path under `slides[]` is identity or creation-time input, exempt on its merits.

**What `null` changes on the wire.** Before, an unmarked option carried no `isCorrect` key. Now it carries `isCorrect: null` wherever the deck is sent in full: to an editor, and to the audience once the solution is revealed. While a quiz question's solution is withheld, `withAudienceSolutions` still drops the key from every option, marked or not, so a withheld mark stays indistinguishable from an unmarked option (REQ056). The results tally is unchanged. It reports `null` for every option of a slide with no marked option, and a boolean for every option once any is marked.

### Slices

- [x] **REQ184/1-max-responses-declared-absence** — `SlideSchema.maxResponses` is `.nullable().default(null)`; every read site resolves `null` exactly as it resolved `undefined` (through `maxResponsesFor`, which `server/preview.ts` now calls instead of its own copy), so an unconfigured slide still follows `allowMultiple`. `"maxResponses"` is out of `SLIDE_OPEN_DEFAULT_GAPS`.
- [x] **REQ184/2-is-correct-declared-absence** — `MultipleChoiceOptionSchema.isCorrect` declares its absence the same way; the results export still reports an unmarked option as `null`, the audience payload's answer-key withholding is unchanged, and `SLIDE_OPEN_DEFAULT_GAPS` is empty and removed. Closes REQ184.

**Done when.** Both fields declare their absence (for example `.nullable().default(null)`, with each read site resolving `null` where it resolved `undefined`), `SLIDE_OPEN_DEFAULT_GAPS` is empty and removed, and the export, the answer-key withholding and the `allowMultiple` fallback behave as before. `mise run check` and `mise run test` stay green.

**Known limits and follow-up, from the pre-merge review (2026-10-25).** None blocks this record; each is recorded so it is not rediscovered.

- **`correctCount` still gives a quiz's answer away while the question is open.** This record closes `isCorrect`; but the public `GET …/results/<slide>` carries `scoring.correctCount` during the open question, so a participant who answers and reads it back learns whether their option was right, and by elimination which one is. From main. Follow-up, to be prioritised before the public release because it lets a participant cheat at a quiz.
- **The presenter's view marks the correct option while the question is open.** That view is not the participant's; whether it is projected is a product question.
