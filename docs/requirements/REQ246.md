## Description

As someone who holds an account, I want deleting it to require its password on every request, so that a person who reaches a signed-in session of mine, a browser left open or a stolen session cookie, cannot delete the account and everything it owns without knowing the password.

Done when `POST /api/auth/delete-user` without the account's correct, non-empty password is refused for every session age and removes nothing: no auth row, no folder, no filing and no folder grant. A request with the correct password still deletes the account and runs the folder sweep (REQ126).

## Notes

**Before this.** `better-auth@1.6.23` (`dist/api/routes/update-user.mjs`, `deleteUser`) verifies a password only when the body carries a non-empty one. Otherwise it accepts a session under `session.freshAge` old, 24 hours by default. A body of `{}` or `{"password":""}` with a session under a day old therefore deleted the account. The account screen (`src/auth.tsx`, `DeleteAccountForm`) always sends the password, so the gap was open only to a request built outside it. Security audit NST16393 (finding 1) raised it.

**How it is required.** `requireDeletionPassword` in `server/accounts.ts` runs as Better Auth's `hooks.before`. On `/delete-user` it refuses a body whose `password` is not a non-empty string with `400 PASSWORD_REQUIRED`; Better Auth then verifies the password a body carries and answers `400 INVALID_PASSWORD` when it is wrong. A before hook runs ahead of the endpoint, so a refusal happens before `beforeDelete` and nothing is swept. The hook runs for `auth.api.deleteUser` calls on the server too, because `auth.api.*` goes through the same hook pipeline.

**The emailed-token route is refused too.** `GET /delete-user/callback` deletes on a verification token and carries no password. No route mints such a token here, because `user.deleteUser.sendDeleteAccountVerification` is not set, but the endpoint is mounted, and a planted `delete-account-<token>` verification row did delete an account through it in a test with the hook removed. The hook refuses the path outright with `400 PASSWORD_REQUIRED`. A `token` in the `/delete-user` body is refused the same way unless the body also carries the password.

**Not the fix: `session.freshAge: 0`.** Better Auth skips the freshness check when `freshAge` is `0`, so every session of any age would then delete without a password.

**Tests.** `server/folders.integration.test.ts`, under "deleting an account": no password and an empty password on a session under a day old are refused with `PASSWORD_REQUIRED` and remove nothing, then the correct password deletes; a session over a day old is refused without a password and deletes with it; a wrong password is refused and removes nothing; the callback route and a body token are refused with a planted verification row and remove nothing.
