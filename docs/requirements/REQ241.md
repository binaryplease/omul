## Description

As a presenter who works by keyboard or with a screen reader, I want the "Share the results" panel to behave like the "Clear the results" prompt beside it, so that I can open it, use it and leave it without a mouse and without losing my place on the page.

The panel is drawn by the shared dialog shell `Modal`, which also draws the deck's other sharing, export and workspace dialogs and the account dialogs. Every one of them gains the same:

- **A dialog in the accessibility tree.** The panel is `role="dialog"` with `aria-modal="true"`, named by its title through `aria-labelledby`, as `ConfirmModal` is (REQ219).
- **Focus goes in on open.** Focus moves onto the panel, unless the dialog's body has already put it on one of its own fields (`autoFocus`), which keeps it.
- **Escape closes it wherever focus is.** It is heard at the document while the dialog is open, not only inside the panel.
- **Focus stays in the panel while it works.** A control that went disabled or was replaced while it had focus ("Create link" while the link is minted) drops focus on the page; the panel takes it back.
- **Focus goes back on close** to whatever opened the dialog, when that is still in the document.
- **Keys typed in the dialog stay there.** An arrow key or Space on the dialog's own buttons no longer reaches the presenter's window-level slide shortcuts behind it.
- **Unchanged:** the backdrop click and the Close button still close it; the panel is not a Tab stop of its own (`tabindex="-1"`); what each dialog shows and does.

## Notes

Defect, **internal**: found by the final UI re-test of the quiz work (finding E2, minor). On the presenter page, "Share the results" opened a panel of plain `div`s with no dialog role. Focus stayed on the trigger, so Escape did nothing; "Create link" disabled the focused button and dropped focus on `BODY`, where Escape did nothing either; only with focus on "Copy link" inside the panel did Escape close it, and focus then landed on `BODY` instead of on the trigger. Reproduced in Chromium at 1440 × 900 on the tree before this fix: no `role="dialog"` in the document, and after Escape the panel was still open with focus on the trigger.

- **Where:** `src/components/ui/Modal.tsx`. Fixed in the shell rather than in `ResultsLinkDialog`, because the shell is the unit every one of these dialogs shares (ADR-0026, ADR-0027) and all of them had the same gap.
- **Escape at the document**, not on the backdrop: a key event only reaches an element's handler when focus is inside it, and a disabled button had just put focus outside.
- **No focus trap.** Tab can still leave the panel; the panel takes focus back only when it has been dropped on the page body. A full trap is not what `ConfirmModal` does either.
- **Tests:** `src/components/ui/Modal.test.ts`: the panel is a modal dialog named by its title, and it is focusable from script but not a Tab stop. Both fail on the tree before this fix. Where focus goes and that Escape closes it from anywhere is behaviour a static render cannot show, so it was checked in the browser, as for REQ219.

## Updates

- 2026-11-01 — Filed from the final UI re-test of the quiz work (E2, minor): the Share the results panel had no dialog role, Escape closed it only with focus inside it, and Create link and closing dropped focus on the page body.
- 2026-11-01 — Shipped. The shared Modal shell is role=dialog, aria-modal, labelled by its title; it takes focus on open unless its body autofocused a field, closes on Escape heard at the document, takes focus back when a disabled or replaced control dropped it on the body, keeps other keys from the presenter's window-level shortcuts, and hands focus back to the opener on close. Tests: src/components/ui/Modal.test.ts (2, both fail before the change). Verified in Chromium at 1440 x 900 on the presenter page: Share the results opens with focus on the dialog, Escape closes it with focus back on the trigger, after Create link focus stays in the dialog and Escape closes it, and Escape from Copy link returns focus to the trigger. 0 console errors.
