## Description

A slide type accepting one number per participant within a configured range, rendering the distribution of the submitted answers.

## Updates

- 2026-08-05 — Guess the Number slide type shipped end to end: "guess-number" joins SlideTypeEnum and INTERACTIVE_SLIDE_TYPES, and a participant estimate is one number on one vote row encoded into VoteSchema.value by encodeGuess/decodeGuess — no new stored field and no new endpoint. One participant holds one guess; re-submitting replaces it, so a room can revise until the reveal. getSlideResults returns the distribution as buckets aligned to the authored step (one column per selectable value, grouped into at most GUESS_BUCKET_LIMIT=24 columns for wider ranges so the histogram stays legible on a projector), plus guessCount and the lowest/highest/average/median guess as explicit nulls before anyone has answered (ADR-0024). Mean and median are both reported because a single wild estimate parts them, which is the conversation the slide exists to start. The shared screen draws the histogram in a dedicated GuessDistribution component shared with the editor preview (ADR-0027), so the picture an author previews is the picture the audience reads; its placement helpers are pure and unit-tested (markers sit on their column, never between two bars). Tests: server/guess.schemas.test.ts, server/guess.integration.test.ts, src/components/GuessDistribution.test.ts. Verified in the browser: three participants guessed on a 0-20/step-2 slide, the shared screen updated live over the WebSocket, and a re-submission replaced a guess rather than adding one (3 responses throughout).
