## Description

Participants can send lightweight reactions on any slide type. Reactions are broadcast to the room and are not stored as answers or counted in any tally.

## Updates

- 2026-08-10 — Reactions on any slide shipped, and shipped as a thing that is never stored: reactionsEnabled is deck state (defaulting closed, ADR-0029) and POST /api/presentations/:id/reactions validates a closed five-member enum (like/love/celebrate/laugh/insight), broadcasts reaction.sent to the room and returns — no collection, no StoredReaction schema, no path from the endpoint to any aggregation, so "not stored as answers or counted in any tally" is a property of the call graph rather than a filter. Any slide type takes one, content slides included; slideId rides along untouched and nothing is keyed by it. Client: a shared ReactionBar/ReactionStream module with one icon+label descriptor per kind (lucide-react, ADR-0022/0026), the bounded self-expiring stream rules in src/reactions.ts composed by both the session slice and the overlay, participant row plus presenter overlay, and the channel switch on the presenter's audience panel and in the editor's deck settings. Rate-limited on the vote budget despite writing nothing (it reaches every socket). Tests: reactions.schemas.test.ts, reactions.integration.test.ts (a 20-reaction burst leaves votes and every tally byte-identical), src/reactions.test.ts, ReactionBar.test.ts, session-slice reducers. docs/api.md carries the endpoint, the channels.settings/reaction.sent events and a Participant channels section.
