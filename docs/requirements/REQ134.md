## Description

A deck can require participants to be signed in. An anonymous join is refused, and the authenticated identity is stored with that participant's answers.

## Notes

### Slices

- [x] **REQ134/1-server-enforcement** — a deck carries `requireParticipantSignIn` (default off); with it on, the join route and every participant write refuse a caller with no account (`refused: "sign-in-required"`), and each participant id is bound on first write to the account whose session sent it, so a second account is refused under it (`refused: "participant-account-mismatch"`). The binding never reaches a client and is erased with the deck. Server, tests and `docs/api.md` only. Built by NST11844-req134-server-signin.
- [x] **REQ134/2-editor-and-join-ui** — the editor shows the switch; an anonymous participant arriving at such a deck is told to sign in and comes back to the deck afterwards. Closes REQ134. Built by NST11849-editor-and-join-ui.

**Known limits and follow-up, from the pre-merge review (2026-10-25).** None blocks this record; each is recorded so it is not rediscovered.

- **A typed answer is lost if sign-in is switched on mid-session.** A participant who joined anonymously and is typing when the presenter turns the requirement on is refused on Send and sent to sign in; when they come back the field is empty. Only one sentence is lost, no stored data, and only in that switch-mid-session case. Follow-up: keep the draft across the sign-in.
- **A second person on a shared device can only go on through "Switch account".** The device binds to the first account that writes ("on first write"), so a second signed-in person is refused each answer with "Signed in as someone else", reload or not. That is the binding as intended; the way out is in the UI.
