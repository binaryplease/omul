## Description

A quiz slide carries a time limit. The window is opened by the presenter, and a submission arriving after it closes is refused with a stated reason rather than silently dropped.

## Updates

- 2026-08-06 — The authored per-question timeLimit is now real at run time. A question opens when the presenter reaches its slide (slideStartedAt on the presentation, broadcast as slide.started) and closes timeLimit seconds later; the server refuses a late answer with 400 (1.5s grace for a tap already in flight, which buys acceptance but no points). Both surfaces render the same countdown from one shared descriptor (src/components/QuizTimer.tsx) on the server's clock via a serverNow-derived offset, so what a participant sees running out is the instant the boundary enforces. timeLimit 0 now means 'no limit' rather than 30. A slide is stamped once on first arrival, so paging back never re-times a question; POST /api/presentations/:id/timer lets the presenter deliberately reopen one, and reset clears the stamps with the votes they timed. Enforcement is live-mode only by construction: a survey has no shared instant a question started.
