## Description

The PDF a deck is rendered to draws every character the deck and its responses actually contain — a Polish `ł`, a Greek or Cyrillic word, a CJK title, an emoji a participant typed into a word cloud — rather than folding them to a nearest Latin letter or to a substitution mark.

## Notes

Raised by the REQ096 implementation, which ships the fold rather than the coverage.

`server/deck-pdf.ts` sets its text in the PDF **standard fonts** (Helvetica / Helvetica-Bold). Nothing is embedded, so the file is small and every reader draws it identically — but their encoding is **WinAnsi**, which covers Latin-1 plus a handful of typographic characters and no more. `winAnsiText()` is what keeps that from being a crash: a character WinAnsi has is kept, one it does not is decomposed and stripped of its combining marks (so `č` prints as `c`, `ą` as `a`), and a run of what survives neither collapses to a single `?`. Without it `drawText` throws on the first unencodable character and the whole export fails over one word somebody typed, which is why the fold is there and not merely tolerable.

What it costs: a deck authored in a script these fonts cannot express exports as a page of `?`, and a Latin-Extended deck exports with its diacritics quietly removed. Neither is silent in the code — both are documented at the endpoint and in `docs/api.md` — but both are a real loss of what the organizer wrote.

The fix is an **embedded font**, which is a decision with a size to it rather than a bug to patch:

- A vendored Latin + Latin-Extended + Greek + Cyrillic face (vendored and bundled, never fetched at runtime) is a few hundred KB and closes everything except CJK. `pdf-lib` embeds TrueType/OpenType through `@pdf-lib/fontkit`; the faces this repo already ships (`@fontsource-variable/figtree`, `@fontsource/dm-mono`) are WOFF2 and would need a TTF/OTF beside them.
- CJK needs a font an order of magnitude larger again, and is the part that decides whether this is one font or a subsetting step.

Subsetting on export would keep the file small and is the shape that scales to both, at the cost of a real font pipeline in a module whose whole point today is that it has none.

Whichever way it lands, `winAnsiText()` stays as the floor for whatever the embedded face still cannot draw — the export must never fail over a character.
