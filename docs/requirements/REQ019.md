## Description

Text and chart colors can be overridden per slide, layered over the deck theme's defaults rather than replacing them.

## Updates

- 2026-08-11 — textColor overrides --color-text for one slide, with the muted and dim steps derived from it against that slide's own canvas; chartColor seeds all eight --color-poll-* series (the seed verbatim as series one, the rest stepped round the hue wheel inside a lightness band) so a slide can be 'the green one' without an organizer hand-authoring a categorical scale and without the eight bars collapsing into one hue. Both layer: a slide that named one names only that one, and everything else is still the deck theme's. The scope re-declares 'color' as well as the token, because index.css resolves --color-text into a computed value high up the tree — the same reason DeckThemeScope re-declares font-family.
- 2026-08-11 — Review fix (NST8763, finding 1 — blocking): a text-only override was writing the whole neutral ramp, so a slide that recoloured only its words also replaced the theme's hand-authored --color-void / surface-raised / surface-hover / border / border-subtle with approximations, and the derived muted and dim steps fell below WCAG AA on a light canvas (muted 6.92 -> 3.91, dim 4.34 -> 2.21 for a text colour byte-identical to the theme's own). Fixed in two parts: neutralRampTokens() is split into surfaceRampTokens() (written only when a canvas was authored) and textRampTokens(), and the slide layer passes SLIDE_TEXT_MIN_CONTRAST (4.5 muted, 3 dim) so each quieter step is walked back towards the words until it clears its floor against the canvas it sits on. The deck-brand layer passes no floor and its output is unchanged. Regression tests: the reviewer's repro, plus a sweep of every built-in theme in both schemes.
