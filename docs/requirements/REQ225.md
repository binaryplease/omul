## Description

As a participant in a presentation whose audience language is not English, I want every quiz and leaderboard text I read, on my phone and on the shared screen, to be in that language, so that a German deck does not switch to English as soon as a result appears. This repairs REQ084 (presentation language) for the surfaces REQ054–REQ057 and REQ059 added, and REQ183/REQ185 (the app menu) on the participant's screen.

- **Results**, on the phone, the shared screen and the shared results page: the solution mark ("correct"), the quiz score note ("1 of 2 answered correctly · 418 of 1000 points on average"), a typed question's "Accepted: …", "No answers yet", "N answers in — they appear once the question is over", the response count ("N responses", "from N participants") and the chart names (pie, donut, "N votes") all come from the deck's dictionary in `src/i18n.ts`.
- **Shared screen**: the countdown ("s left", "Time's up" and the spoken thresholds), what stands in for a tally that is not shown yet ("Results appear when the time is up.", "… once the question is closed to answers.", "Waiting for responses...", "Waiting for scores..."), "Results are private" and "Results are hidden".
- **Leaderboard**: the caption ("Top 1 across 1 quiz question") and the name of a row whose holder stated none ("Player DB5452"). The server still sends the English label. The client recognises a derived label by comparing it with `leaderboardEntryLabel(entryId)` and rewords it from the handle (`leaderboardEntryHandle`). A stated name is never reworded.
- **App menu on the participant's screens**: the trigger's name ("Appearance, feedback and legal"), its close control, the Appearance section and theme names, "Send feedback", the Legal section and its text names, "(opens in a new tab)" and the feedback dialog (whose form already had translated labels).
- **Plurals** are chosen by the language's own rules (`Intl.PluralRules`, through `countPhrase`), not by `count === 1`. French and Portuguese use the singular for 0; where a language has a "many" form, the "other" form is used.
- **Presenter-only chrome stays in the app language**: Restart timer and its hint, Reveal/Hide results, the count/percentage switch, Close submissions, and the app menu on the presenter's and editor's pages.

## Notes

Defect, **internal**: found by a UI test pass of the quiz feature (minor m1). The pass ran on `f3bd62e`, which is not on this branch or on `main`: it is a single commit on top of `f55a768` that adds the word-cloud submission control and touches no quiz code, so the quiz code it tested is `f55a768`'s, which is on `main`. With the audience language set to Deutsch, the strings listed above stayed English on the phone and on the shared screen, on the leaderboard among other places.

How the words flow: the dictionary gains a `locale` and `PluralForms` values. Each surface maps them in one place: `resultLabelsFor` (Results.tsx, with the leaderboard's labels nested), `leaderboardLabelsFor` and `appMenuLabelsFor`. The English constants (`RESULT_LABELS_EN`, `LEADERBOARD_LABELS_EN`, `APP_MENU_LABELS_EN`) are derived from the English dictionary, so English has one source. `PresenterSlideView` reads the deck's dictionary for the room's text and keeps its own controls in English. `THEME_OPTIONS` no longer carries names, which now live in the dictionary. `configuredLegalLinks` returns each text's `field` so the menu can word it.

The "Reveal when you're ready." hint beside a hidden tally was dropped: the Reveal button under it says the same thing, and the line it was attached to is now in the deck's language.

Left for later, outside quiz and leaderboard: the participant's controls on other slide types ("Select all that apply", ranking and 100-points buttons, …), the multi-select note under a poll's results, the results of scale, ranking, grid, guess and pin slides, the slide-type label above the question on the shared screen, and the shared results page's own chrome are still English.
