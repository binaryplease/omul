## Description

As a participant in a scored quiz on a deck that asks for a name on joining, I want the leaderboard to show me under the name I gave, so that I and the room can find me in the standings. This repairs REQ059 (the leaderboard slide) against REQ076 (asking participants for a name).

On a deck that asks for a name on joining, every leaderboard row the slide shows is labelled with the name its holder stated, in its latest spelling if they corrected it. A participant who stated no name keeps the derived "Player XXXXXX" label, and so does every row of a deck that does not ask for names, including a deck that asked earlier and has since turned the switch off. The row keeps its one-way handle, its place and its order, so the "You" marker on a participant's phone still finds their own row, and their own scorecard reports the same label. The board carries the name as the row's label and nothing else: no participant id and no time it was stated, and no name for a row below the slide's cut. Stating or correcting a name, and turning the deck's switch on or off, re-sends the board to everyone watching. A long name or one with emoji truncates on a single line on the phone and on the shared screen and never pushes the score off the row.

## Notes

Defect, **internal**: found by a UI test pass of the quiz feature on `f3bd62e` (major M2). On a deck with "Ask for a name on joining" on, a participant joined as "Jürgen 🦊 Müller-Lüdenscheidt", and the presenter's participants panel listed that name. The Leaderboard slide on the shared screen and on the phone showed "Player DB5452". Reproduced on the branch before this fix by `server/leaderboard.integration.test.ts`: the row's label stayed `Player …` after the participant stated a name.

**What was wrong.** REQ059 shipped before any requirement asked participants for a name, so `leaderboardEntryLabel` always derived the label from the row's handle, and its docblock said no catalog entry asked for a nickname. REQ076 then added the names as a roster for editors and exports, and kept the leaderboard anonymous on purpose. Its docs said the roster "does not re-point the leaderboard". The two features then disagreed in the one place where a room plays under names.

**What closes it.**

- `server/schemas.ts`: `leaderboardEntryLabel(entryId, statedName)` returns the stated name when there is one, and otherwise the derived `Player XXXXXX`. `rankLeaderboardEntries(totals, statedNames)` takes a handle → name map and changes only `label`. The order stays by points, then handle, so a corrected name never reshuffles level rows.
- `server/services/presentations.ts`: `leaderboardNamesFor` reads `participantNameLookup` **only while `deckRequiresParticipantName` is true**. That gates on the switch, not on whether anything is stored, because a deck that turned names off still holds them for its exports (REQ076) and the board is public. `rankQuizDeck` maps each ranked participant's name onto their handle. The results payload's `entries` are still cut at the slide's size, so only the projected rows carry a name. `getParticipantScorecard` labels the participant's own card the same way. `stateParticipantName` and a PATCH of `requireParticipantName` both call `broadcastStandings`, which is coalesced like an answer.
- `src/components/Leaderboard.tsx`: the row label gets `min-w-0` so it truncates inside its flex row instead of overflowing. Its `title` carries the full name. The header comment now states the REQ218 rule in place of the "no catalog entry asks" rationale.
- `docs/api.md`, the REQ076 comment block in `server/schemas.ts` and the participant-name route description now record the exception. A stated name reaches the audience in exactly one place: as the label of a projected leaderboard row, while the switch is on.

**Why public.** The leaderboard payload is unauthenticated, like every results read, so on a named deck the projected rows' names are readable by anyone who can read the board. That is the point of the fix: the board is projected to the room. The roster itself stays edit-only, and the results link (REQ098) gains nothing an anonymous reader does not already have.

**Left as it was.** The words "Player" and the rest of the board's chrome on the shared screen are not yet in the deck's language (protocol item m1, a later step).

## Updates

- 2026-10-30 — Leaderboard rows on a deck that asks for names now carry the stated name (latest spelling) as their label; unnamed participants and decks that do not ask keep 'Player XXXXXX'. leaderboardEntryLabel/rankLeaderboardEntries take the stated names; the service reads them only while requireParticipantName is on, puts them on the projected rows' label and nothing else, labels the participant's own scorecard the same way, and re-broadcasts the standings when a name is stated or corrected and when the switch flips. Row label truncates (min-w-0) on phone and shared screen. Tests: server/leaderboard.schemas.test.ts (4 new), server/leaderboard.integration.test.ts (6 new, 4 fail without the fix), ws.integration.test.ts 'a corrected name re-broadcasts the leaderboard (REQ218)' (fails without the broadcast).
