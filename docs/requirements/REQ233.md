## Description

As an organizer running a scored quiz, I want the leaderboard on the shared screen to count a quiz question only once the room may see its verdict, so that nobody in the room can learn the answer key by watching the projector, and a question I set to "Private" never shows up there. REQ228 closed this for the phones: the board they are sent, and every participant's own card, count only the questions `quizVerdictVisibleToAudience` (`server/schemas.ts`) releases. The presenting view and a second screen read the same board with the edit token, and that read counted every question. During a running timed question the presenter can move to the leaderboard slide; a participant who knows their own row then answers under fresh participant ids, one per option, and watches which projected row scores. That is the oracle REQ228 closed, reopened on the wall. Under "Private" the projected board showed results the organizer had kept from the room.

The room is the audience, so the board drawn for it follows the audience's reading:

- **The single-slide results read** (`GET /api/presentations/:id/results/:slideId`) of a leaderboard slide — what the presenting view polls and what every phone reads — is summed only over the released questions for every caller, an editor included. A running question, an "On click" question before its reveal and a "Private" question move no row, and nobody is ranked on them alone. "Instant" counts a question once it is over.
- **The broadcast** (`results.updated` from `sendStandings`) already was the audience's reading and is unchanged, so the presenter's poll and the frames it receives now agree.
- **The all-slides results read** (`GET /api/presentations/:id/results`) is the room's board for every caller too, an editor included. It feeds the shared results page (REQ098), which the organizer's browser reads with the edit token and which can be projected while a question runs (REQ214).
- **The organizer's own surfaces** keep the whole standings for an editor: the results breakdown (`…/segments`), the results export (`results.xlsx`, `deck.pdf`), and the preview's dry run. Everyone else, results link included, reads the room's board there as before.
- **Fail-safe default.** Counting every question is an opt-in of the reading surface, honoured only beside an edit credential. A surface that does not opt in gets the room's board.

## Notes

Hardening, **internal**: finding 2 of security review NST13303 of the REQ228 chain. It answers the question REQ228's Notes left open (whether the projected board should follow the audience's reading). The default is that it does: a credentialed client drawing for the room must not show what the room may not read.

As shipped (2026-11-01):

- **The opt-in** is `ResultsCaller.wholeStandings` (`server/schemas.ts`). `quizDeckCountedFor` (`server/services/presentations.ts`) lifts the release gate only for `canEdit && wholeStandings`. Everything else in the caller is unchanged: an editor still reads a running quiz question's own tally and key on the single-slide read, and the presenting view keeps those off the projector itself (REQ215/REQ056). A leaderboard spans several questions, so its rows cannot be filtered on the client the same way. The server has to sum it for the room.
- **Who sets it** (since 2026-11-24): the segments route (it spreads the caller and adds the flag, which takes effect only for an editor), `getResultsExport` (behind `requireEdit` on `results.xlsx` and `deck.pdf`), and the preview's `presenterResults`. The preview's answers are generated, so nothing there can leak a key, and a board that waited for releases would preview nothing. The preview's `audienceResults` reads the room's board as before.
- **Why the all-slides results route does not set it:** that route feeds the shared results page, and the organizer's browser reads it with the edit token. The page can be projected while a question runs (REQ214), so a board summed over every question there is the same oracle on the wall. Do not put `wholeStandings` back on it. The page still hides a running quiz slide's own tally (`quizQuestionIsRunning`), and the editor still receives that tally and key on this read (REQ215). A leaderboard spans several questions, so the page cannot hide a running question's share of it on the client.
- **Still open:** the shared results page also mounts the breakdown (`SegmentedResults`) on a leaderboard slide, and the segments route gives an editor whole standings. An organizer who picks a grouping on a projected results page during a running question therefore still shows that question's points per group.
- **The client** needs no change in behaviour. `PresenterPage` polls the single-slide read, which now returns the room's board, so the board on the projector no longer jumps between the editor's poll and the room's broadcast frame.
- **Tests:** `server/quiz-verdict-withheld.integration.test.ts`, "The board the presenter draws for the room" — the review's probe (one fresh id per option during a running "Instant" question, read with the edit token after each answer, counted once the question is over), "On click" until the reveal, "Private" through close and end of the deck, and the all-slides results read under "Private" counting nothing for an editor either. The three scenario tests fail on the tree before this change, checked by running the new test file against an export of `316d2fc`, the commit this change was made on. The REQ228 test that asserted the editor's single-slide read counted a running question was narrowed to the audience and results-link reads.
- **Who reads which board** is pinned in the same file, "Who reads the whole standings": on an "Instant" deck with one question over and one still running, `GET /results` gives an anonymous caller, a results-link holder, the edit token and both credentials together the board summed over the released question only; `api.getSharedResults`, run from a browser holding the edit token and the results link, gets the same board; `…/segments` refuses a non-editor a leaderboard breakdown (`identifiable`) and gives the edit token each group's whole standings; `getResultsExport` sums every question.
- **The `canEdit` half of the guard** is pinned by "wholeStandings without canEdit lifts nothing", which calls `getAllResults` with `wholeStandings: true` beside no credential, `canEdit: false` and `hasResultsLink: true`, and expects the released-only board each time. No route sends a non-editor through with the flag any more, so this direct call is the test that holds the `&&`.
- **Docs:** `docs/api.md` (the leaderboard section and the answer-key section) and the OpenAPI descriptions of the single-slide and all-slides results reads. The answer-key descriptions of `GET /presentations/:id` and `GET /join/:code` were corrected in the same change to describe the reveal-setting gate in place since REQ228's second fix: "Instant" once over, "On click" after the reveal, "Private" never.
