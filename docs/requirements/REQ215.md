## Description

As an organizer running a scored quiz, I want the per-option counts of a select question to be withheld on the wire from everybody who cannot edit the deck while that question is still being answered, so that a participant cannot copy the majority's answer by reading the results payload their own browser receives. The same holds for the correctness half of the quiz score on that payload (`correctCount`, `totalPoints`, `averagePoints`, `correctShare`): each moves when one correct answer lands, so a participant who answers under a fresh id and reads the next frame would learn the key from it, on a typed question as much as a select one. This hardens REQ056, which already withholds the answer key and a typed question's answers on the same terms.

## Notes

Hardening, **internal**: found while fixing REQ214. No screen draws the counts while the question runs any more (REQ214 gates the shared screen and the shared results page; participant phones already waited). But under `instant`, `aggregateSlideResults` in `server/services/presentations.ts` still puts every option's `count` in the payload it returns to an audience caller, and the `results.updated` broadcast after each answer carries it to every socket in the room.

The typed tally is the precedent: there `entries` is withheld (explicit `null`) until the question is over, because on a scored question the answer most of the room gave is the answer. A select question's counts say the same thing. A fix needs a withheld shape for the counts that clients, `server/results-export.ts`, segmentation and `cli/payload.ts` all read without mistaking it for zero answers. The gate is `quizQuestionIsRunning` or `solutionVisibleToAudience`, and an editor is exempt as it is for the key.

As shipped (2026-10-31):

- **The gate** is `quizResultVisibleToCaller` (`server/schemas.ts`): `canEdit`, or `solutionVisibleToAudience`. A running question always fails the second (`quizQuestionIsRunning` implies it), and so does a question not opened yet, so one test covers both halves of the gate above. It is deliberately not `tallyVisibleToCaller`: the results link (REQ098) lifts the reveal mode, and it authorizes no running question's key, so it does not lift this either.
- **The withheld shape** is an explicit `null` on every `options[].count`, on the four correctness fields of `scoring`, and on `typedAnswers.distinctCount`. That last one is withheld as well because a guess typed under a fresh id that leaves it unchanged is one somebody already gave. `totalVotes`, `respondentCount`, `scoring.answeredCount` and the window fields stay. `quizResultWithheld` reads the shape off `scoring.correctCount === null`, which a published quiz tally never carries: it is `0` when nobody has answered. The predicate is separate from `isWithheldTally` because this tally is published, and a client that drops withheld frames would drop the answered count with it.
- **Every surface** lands on `aggregateSlideResults`: both results endpoints, the `results.updated` broadcast, the preview's audience pane, and each group of a segmented read *of* the question. Segmenting *by* such a question is its own path. Its groups are the question's options sized by who picked each, so it answers `withheld: true` with the new reason `quiz-not-over`.
- **Consumers.** `ResultsDisplay` draws a withheld quiz result as the existing "*n* answers in — they appear once the question is over" line, for both answer modes, and the score line draws nothing from null numbers. `SegmentedResults` explains `quiz-not-over` in its own sentence. `server/results-export.ts` already read every count through a nullable reader, and it is fed `canEdit: true` anyway. `cli/protocol.ts` restates the predicate (held to the server's by `cli/protocol.test.ts`), and `omul results` prints "answers withheld until the question is over" rather than leaving the nulls to read as zeros.
- **Not covered here:** the participant scorecard and the leaderboard standings, which carry per-participant verdicts and points of a running question by another route. They are a separate item.

## Updates

- 2026-10-30 — Filed while fixing REQ214. The counts are no longer drawn on any screen during a running question, but they still ride the audience results payload and the results.updated broadcast under instant.
- 2026-10-31 — Shipped. While a quiz question is running or its solution is not yet the audience's, a caller who cannot edit the deck reads every option count, the correctness half of scoring (correctCount, totalPoints, averagePoints, correctShare) and a typed question's distinctCount as explicit null, on both results endpoints, the results.updated broadcast, the preview's audience pane and segmentation of the question; grouping by such a question is withheld as quiz-not-over. Gate quizResultVisibleToCaller (canEdit or solutionVisibleToAudience; the results link does not lift it), shape read by quizResultWithheld. Results views draw 'n answers in' instead of zeros, the CLI restates the predicate. The anonymous mid-window read in the quiz suite that expected correctCount 1 became an editor read plus an audience read expecting null. Scorecard and leaderboard standings are not covered here.
