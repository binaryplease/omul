## Description

As an organizer running a scored quiz, I want the per-option counts of a select question to be withheld on the wire from everybody who cannot edit the deck while that question is still being answered, so that a participant cannot copy the majority's answer by reading the results payload their own browser receives. This hardens REQ056, which already withholds the answer key and a typed question's answers on the same terms.

## Notes

Hardening, **internal**: found while fixing REQ214. No screen draws the counts while the question runs any more (REQ214 gates the shared screen and the shared results page; participant phones already waited). But under `instant`, `aggregateSlideResults` in `server/services/presentations.ts` still puts every option's `count` in the payload it returns to an audience caller, and the `results.updated` broadcast after each answer carries it to every socket in the room.

The typed tally is the precedent: there `entries` is withheld (explicit `null`) until the question is over, because on a scored question the answer most of the room gave is the answer. A select question's counts say the same thing. A fix needs a withheld shape for the counts that clients, `server/results-export.ts`, segmentation and `cli/payload.ts` all read without mistaking it for zero answers. The gate is `quizQuestionIsRunning` or `solutionVisibleToAudience`, and an editor is exempt as it is for the key.

## Updates

- 2026-10-30 — Filed while fixing REQ214. The counts are no longer drawn on any screen during a running question, but they still ride the audience results payload and the results.updated broadcast under instant.
