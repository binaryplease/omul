## Description

As a participant on a slow network, I want the option I tapped to show as my choice at once, with a short "Sending…", so that I know the tap registered and do not wonder whether to tap again. This repairs REQ054 and REQ055 (the quiz question in both answer modes) and REQ147 (an answer stays final), whose guard against a second submission disabled every option without saying which one was on its way.

- On a single-choice slide (every quiz question, and a single-choice poll) the tapped card is drawn selected and `aria-busy` while its answer is sent, with a spinner and "Sending…" on it. The other cards step back. The live region under the cards says "Sending…" (REQ221).
- On a typed quiz question the submit button reads "Sending…" and the region says so.
- The words are in the deck's language (`answerSending`).

## Notes

Defect, **internal**: found by a UI test pass of the quiz feature (polish p2). The pass ran on `f3bd62e`, which is not on this branch or on `main`: it is a single commit on top of `f55a768` that adds the word-cloud submission control and touches no quiz code, so the quiz code it tested is `f55a768`'s, which is on `main`. With a 24 s delay simulated, all options were disabled and none was marked.

The pending option is local state (`pendingOptionId`) set before the vote goes out and cleared when it settles. `choiceCardState` reads it with what the server holds, so the card goes straight from pending to selected without a gap. A multi-select slide toggles a selection, so marking a tap as chosen would be wrong when the tap removes one. There the region's "Sending…" is shown as text under the cards.
