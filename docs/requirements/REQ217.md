## Description

As a participant in a scored quiz, I want to keep the points I earned for an answer when the presenter restarts that question's timer, so that my score depends on how fast I answered, not on whether the presenter reopened the question afterwards. This repairs REQ057 (the question's window and the restart that reopens it) and REQ054/REQ056 (points from correctness and speed).

Restarting a question's timer opens a fresh window only for participants who have not answered yet. Every answer already given keeps the score it earned against the window it was given in. Whoever already answered still cannot answer again (REQ054, REQ147). Re-marking which option is correct, or which typed answers are accepted, still re-scores the whole room. Paging away from a question and back does not move its window and changes no score. The presenter's "Restart timer" control states this in its tooltip and its accessible description.

## Notes

Defect, **internal**: found by a UI test pass of the quiz feature on `f3bd62e` (major M1, reproduced twice). After a window ended, the presenter clicked "Restart timer". A participant who had answered correctly fell from +836 to +500 (total 1755 → 1419) without doing anything. In the second reproduction an answer given with about 16 s of 20 s left showed +500 instead of about +900. A late joiner answering in the reopened window got +753, more than the fastest answer of the first window. Reproduced on the branch before this fix by `server/quiz.integration.test.ts`: the pre-restart answer's points dropped to `QUIZ_CORRECT_POINTS` once the timer was restarted.

**What was wrong.** A quiz answer's speed was measured from the slide's `slideStartedAt`, read when scoring. A restart moves that stamp forward, so every earlier answer had a negative elapsed time against it. `scoreQuizAnswer` scores a negative elapsed time as the correctness half with no speed bonus. That rule was meant to stop the slowest pre-restart answer from looking instant, but it took the speed bonus away from everyone who had answered.

**What closes it.**

- `server/schemas.ts`: `StoredVoteSchema` gains `quizWindowOpenedAt` (`.nullable().default(null)`), the opening instant of the window a quiz answer was accepted in. This is the one departure from "points are derived, never stored", and it stores only *when the window opened*. Correctness is still read from the slide as it now stands, so re-marking the solution re-scores the room.
- `server/services/presentations.ts`: `submitVote` writes the stamp inside the per-participant write lock (REQ147), from the same `slideStartedAt` value the deadline check used. So the window that accepted an answer is the one it is timed against. `scoreQuizSlide` times each answer from its own stamp through `answerWindowOpenedAt`, and falls back to the slide's current stamp for an answer stored before the field existed. `restartSlideTimer` no longer re-broadcasts the standings, because no score moves. Instead it re-sends the quiz slide's room tally, which is withheld again now that the question is running (the step-2 review's NIT 5).
- `src/components/PresenterSlideView.tsx`: `RESTART_TIMER_HINT` ("Reopens this question for participants who have not answered yet — answers already given keep their points") is the button's `title` and its `aria-describedby` text. The description sits in a screen-reader-only span *beside* the button, so the accessible name stays "Restart timer".

**No confirmation, deliberately.** The restart no longer destroys or changes anything already earned. It moves one window, for the participants who have not answered. A confirmation would add a second click to a live stage control in front of a room, and would guard against no loss.

**Navigation.** `withSlideOpenedOnce` already stamps a slide only on first arrival, and nothing but the restart and a reset moves the stamp. The protocol confirmed this (passing check 10). `paging away from a question and back changes no score` in `server/quiz.integration.test.ts` now holds it as a score property, not just a stamp property.

**Left as it was.** An answer stored before this change, on a deck live across the upgrade, is still timed against the slide's current stamp. If that question is restarted, the answer keeps the correctness half with no speed bonus, as before. `an answer stored before votes carried their window is timed as it always was` covers this. After the first window closes, the room was already sent the key (REQ216). A participant who had not answered may have seen it before answering in the reopened window. That comes from offering a restart after a reveal at all, not from the scoring, and this requirement does not change it.
