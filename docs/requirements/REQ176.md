## Description

As a reader of this repository — a contributor, a self-hoster, or a stranger arriving at it after publication — I want the documentation, the module comments, the dev tooling and the requirement catalog to name one product, so that nothing in the tree reads as a fork, an abandoned rebrand or a second thing.

## Notes

The identifier rename is worth nothing if the tree still explains itself in the old name. `mise run triage`'s description, the flake's dev-shell banner, the email-preview gallery's title, the vendored `binp-docstore` consumer note, the module headers in `rate-limit.ts` and `accounts.ts`, the `AGENTS.md` heading, `docs/*.md` throughout, and ten requirement files' Description and Notes sections all carried it.

**Nothing is left, including the history.** An earlier pass of this requirement closed with two categories deliberately kept — the append-only requirement update logs and `task/*.md` — on the grounds that neither is prose anybody may revise. The owner overruled that on 2026-08-29: a reader grepping this repository for context should never surface a name that names nothing here, and that dilution outranks the append-only convention which had protected the residue. Both are in scope, and the residue is gone. This paragraph does not name the string it is about, for the same reason the negative-assertion guards were dropped below: a sentence quoting the retired name is itself an occurrence of it, and it would put the last hit in the one file whose subject is their absence.

The sweep of that history distinguished two kinds of occurrence, and they did not get the same treatment.

1. **The product's own name.** The bare name, the operator variables, the two token headers, the browser storage keys, the store filename, the export marker and file extension, the sample host. Each names *this product and nothing else*, so each was rewritten to its current spelling and nothing became false. Where a sentence's subject *was* the old spelling — a decision to leave a key alone, a check that a retired header no longer authorizes — it was restated in terms that do not name it, since renaming it there would have made the sentence contradict itself.
2. **Identifiers of things outside this repository that genuinely still carry the old spelling.** An archived predecessor repository, its registry paths, a live vhost, a host bind-mount path, a secret path, another repository's deploy configuration. Rewriting these would have named registries, hosts and repositories that do not exist under the new name, and a false record dilutes context worse than a stale one. Where the reference was incidental to an otherwise-live entry, the sentence was restated without it. Where a whole entry existed only to track the predecessor's registry, host or deploy path — REQ145's day-long chase of a GHCR `403` and the deploy topology of a host this product does not run on — the entry was retired, because it has no reader left and its requirement's Description and Notes already carry what is still true.

`AGENTS.md` stated three rules this sweep contradicts — the append-only `## Updates` section, the closed `task/*.md` log, and a clause telling a reader to take an unfamiliar identifier as an old spelling. All three were amended in the same change rather than silently broken: the first two name this sweep as the one exception taken and refuse it as a precedent, and the third no longer describes this tree.

An earlier pass of this requirement declared two further categories — a compatibility layer carrying the old name deliberately, and the negative-assertion guards holding that name's absence. Both are gone. The compatibility layer was withdrawn with REQ174 and REQ175 once the premise behind it (a live product with deployments, browsers and files to protect) turned out to be false, and a guard asserting that a string does not appear is itself an occurrence of that string, guarding against a name that now exists nowhere in the source. What those guards were worth is kept as the positive assertion underneath: an email's masthead and a PDF's `Creator` are checked to name `omul`, which is the property that was ever wanted.

Where a sentence was *about* the old identifier rather than merely using it, it was reworded rather than falsified. REQ167's "not in scope" paragraph and REQ170's naming-divergence paragraph name the things they exclude by role. `OPEN_SOURCING_PROGRESS.md`'s "still the identifier everywhere under the surface, by decision" bullet records the answer rather than the deferral: the position it stated — that renaming the storage keys orphans stored edit tokens — rested on there being stored edit tokens, and there are none. Where prose named the GitHub repository or the deploy host's secret by slug, it names them by role instead, since both belong to operations and to the separate private infrastructure repository that owns the deploy configuration, and both are stated correctly the day operations acts.

Out of scope, and each for a stated reason: the repository, registry and handle names (operations, `Name.md`'s *Betrieb* row); the deploy configuration, which is a separate private infrastructure repository's; the private sidecar's own prose beyond the business record behind these three requirements; and the brand itself, which shipped as REQ166–REQ169.

**Done when.** A case-insensitive `rg` for the retired name over the tracked tree returns **zero** occurrences — no exempt directory, no exempt section; no symbol in `server/` or `src/` is named for a retired spelling; every security decision carried by a retired update-log entry survives in its requirement's `## Notes`; `AGENTS.md` records the decision that made the history sweep legitimate; and the repo's gate and test task (both named in `AGENTS.md`) stay green.
