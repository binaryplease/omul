## Description

Free-text answers on a slide can be grouped into themes. The grouping is stored beside the answers, is editable, and leaves the individual answers intact.

## Notes

### Slices

- [x] **REQ114/1-theme-store** — an editor of a deck can create, rename and delete named themes on a word-cloud or open-ended slide and assign or unassign that slide's answers to them; the grouping is stored beside the answers, readable by editors only, and never changes, hides or deletes an answer. Server and tests only. Built by NST11814-req114-theme-store.
- [x] **REQ114/2-grouping-ui** — editors see a free-text slide's answers grouped by theme and create, rename, delete themes and move answers between them in the client, on top of slice 1's API. Built by NST11817-req114-grouping-ui. The strip it built is out of the editor and unmounted since 2026-11-02; see "The grouping UI (slice 2)" below.
- [ ] **Results-page move** — themes move to the Results page with a new grouping UX. Open follow-up; REQ114 stays `in-progress` until it lands.

### The theme store (slice 1)

- **Where:** `server/services/answer-themes.ts` (the `answerThemes` collection, bounds, the per-slide lock) and `server/routes/answer-themes.ts` (`GET`/`POST /api/presentations/:id/slides/:slideId/answer-themes`, `PATCH`/`DELETE …/answer-themes/:themeId`, `PUT /api/presentations/:id/answers/:answerId/answer-theme` with `{ themeId }` or `{ themeId: null }`). Shapes in `server/schemas.ts` (`AnswerThemeSchema`, `StoredAnswerThemeSchema`, `slideAnswersAreGroupable`); documented in `docs/api.md` under "Grouping free-text answers into themes".
- **Shape:** a theme is `{ id, slideId, name, answerIds, createdAt }`; membership is the `answerIds` list on the theme, so the vote rows are never written. An answer is in at most one theme on its slide; `answerIds` are the results payload's `responses[].id` / `answers[].id`.
- **Access:** read and write both go through `requireEdit` (owner, edit token, `edit` grant). Nothing is broadcast — slice 2 refetches after a change.
- **Bounds:** names trimmed, 1–80 characters; at most 50 themes per slide.
- **Erase:** `eraseParticipantRecords` drops the deck's themes, so both reset (REQ101) and delete (REQ146) do; the REQ027 delete pulls the answer out of its theme after removing the row, under the same per-slide lock an assignment checks the answer under. A theme emptied that way stays.
- **Open for slice 2:** a slide removed from the deck by authoring leaves its themes stored until the deck is reset or deleted, as its answers are; a slide re-authored into another type answers `400` `slide-type` on every theme route.

### The grouping UI (slice 2)

**The strip is out of the editor and unmounted.** The editor shows only pre-presentation content, so `src/pages/CreatePage.tsx` no longer imports or draws `<AnswerThemesStrip/>`, and no other page does. The five server routes, the `answerThemes` collection, the schemas and `docs/api.md`'s description of the routes stay, and an editor's stored themes are neither changed nor deleted. No page offers the grouping until the follow-up lands. `src/components/AnswerThemes.tsx`, its five calls in `src/api.ts` and its tests stay in the tree, so the follow-up can decide what it reuses. The follow-up moves themes to the Results page with a new grouping UX, and the strip's removal from the editor still has to be re-tested in the second acceptance run.

The rest of this section describes that module as it stands. The grouping surface is `src/components/AnswerThemes.tsx`. `<AnswerThemesStrip/>` takes a deck id, a slide id and a slide type. It is closed to one line until opened, and opening it reads the slide's results (`api.getResults` — a word cloud's editor-only `answers`, an open-ended slide's `responses`) together with its themes. Each answer is listed as written, under its theme or under "Ungrouped". A native `<select>` on each answer puts it into a theme, moves it, or takes it out. Themes are added from a name field whose button is disabled with its reason (blank name, or 50 themes reached), renamed in place, and deleted after a confirmation. Every write re-reads, because nothing is broadcast. `groupAnswersByTheme()` is the one split of answers into groups, and it counts the members a theme holds that the list does not name (answers the profanity filter withholds) rather than dropping them. The five calls are `api.listAnswerThemes` / `createAnswerTheme` / `renameAnswerTheme` / `deleteAnswerTheme` / `assignAnswerTheme` in `src/api.ts`, each theme parsed through `AnswerThemeSchema`. `src/components/AnswerThemes.test.ts` holds the placement: no non-test module under `src/` imports the surface, and `components/AnswerThemes.tsx` is the only module that calls a theme route. Its copy is English literals, like the other editor strips; `src/i18n.ts` is the participant dictionary.

**The strip states its own scope.** Themes appear on no live surface, and a tester who did not know that went looking for them on the presenter's screen and could not tell whether the feature worked. So the closed strip's marker reads `ANSWER_THEMES_SCOPE` ("Editors only, not shown live", in the presenter-notes strip's marker shape), and the open panel starts with `ANSWER_THEMES_PURPOSE` in every state, a failed read included: themes are sorted by hand for the editor's analysis, and the presenter screen, the shared screen, participants' phones and the results link show the answers without them. The answer count line adds that answers sent since the list was read appear on refresh, since nothing is broadcast. Showing themes on any live surface would be a new requirement, not a change to this one. Nothing draws this copy while the module is unmounted. `ANSWER_THEMES_PURPOSE` still says "here in the editor", and the follow-up rewrites it.

**Known limits and follow-up, from the pre-merge review (2026-10-25).** None blocks this record; each is recorded so it is not rediscovered.

- **Answers the profanity filter holds are not in the themes.** They are missing from the theme groups and from the strip's count ("1 answer, 1 ungrouped" where two were given). That follows from REQ085's rule that a withheld answer reaches no surface; whether the deck's editors should see such answers while they group is a follow-up question.
