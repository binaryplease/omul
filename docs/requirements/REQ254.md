## Description

As an operator of a NixOS host, I want to enable omul with `services.omul.enable = true` from this repository's flake, so that the server is built by Nix, runs under systemd as an unprivileged user, keeps its data in a state directory, and is updated with the rest of the system. The flake exports the server as `packages.omul-server` and the module as `nixosModules.default`, and a NixOS VM test in the flake's `checks` proves that a machine with the module enabled serves `/api/health`, lets a deck be created and joined, and keeps the deck across a restart of the service. The README presents the module as the recommended self-hosting path and the container image as the alternative for hosts without NixOS.

## Notes

**Why this record exists.** Before it, the flake built only the command-line client (REQ180). The server was packaged as a container image (REQ172) and documented as a hand-written systemd unit on a plain Linux host (REQ249). A NixOS host had no declarative way to run it.

**The server package** (`nix/server-package.nix`). Two derivations:
- `bun install --frozen-lockfile --ignore-scripts` runs in a fixed-output derivation, because the build sandbox has no network. Its `outputHash` is `serverNodeModulesHashes` in `flake.nix`, one value per system, because Bun installs only the running platform's native optional dependencies (rolldown, lightningcss, the Tailwind oxide engine). Only `x86_64-linux` has a value, so only `x86_64-linux` has `packages.omul-server` and the VM test.
- The build runs `vite build` and `bun build server/index.ts --outdir dist/server --target bun` with `NODE_ENV=production`, as the `Dockerfile` does. The result is `dist/client` and `dist/server` under `share/omul/`, and `bin/omul-server` runs the bundle with the Bun from the store. The bundle needs no `node_modules` at run time; the runtime closure is Bun with the libraries it links (glibc, libgcc) and bash for the wrapper script.
- **Running cost:** every change to `bun.lock` needs a new hash, or `nix build .#omul-server` fails with a hash mismatch. `docs/maintaining.md` says how to obtain it.

**The module** (`nix/module.nix`). Options: `enable`, `package`, `port` (default 3000), `openFirewall` (default false), `secretFile` (required), `baseHost`, `trustProxy` (default 0), `adminEmails`, `generationApiKeyFile`, `environment`, `environmentFile`. The option descriptions follow the variable table in `README.md` and the state section of `docs/deployment.md`.
- `secretFile` and `generationApiKeyFile` reach the service as systemd credentials (`LoadCredential=`). A start script exports them as `BETTER_AUTH_SECRET` and `GOOGLE_GENERATIVE_AI_API_KEY` right before it runs the server, so neither value is in the Nix store or in the unit's `Environment=`. The module asserts that neither path, nor `environmentFile`, is in the Nix store.
- Without `generationApiKeyFile`, deck generation (REQ007) stays off.
- `DynamicUser=yes`, `StateDirectory=omul`, `DATABASE_PATH=/var/lib/omul/omul.sqlite`, so every database file is in `/var/lib/omul`. Hardening: `ProtectSystem=strict`, `PrivateTmp`, `PrivateDevices`, `PrivateUsers`, an empty capability set, `RestrictAddressFamilies` to IPv4, IPv6 and Unix sockets, and `SystemCallFilter=@system-service ~@privileged`. `MemoryDenyWriteExecute` is not set, because Bun's JavaScript engine compiles code at run time.
- **No `host` option.** The server listens on `0.0.0.0` in production (`server/index.ts`) and has no setting for the bind address; that setting is REQ250. The module therefore opens no firewall port unless `openFirewall` is set.
- Further variables (`BREVO_API_KEY`, `OMUL_SIGNUP_DISABLED` and the rest of `docs/deployment.md`) go through `environment` (non-secret, written into the store) or `environmentFile` (read by systemd as root).
- Reverse proxy, TLS, DNS and backups are not the module's.

**The VM test** (`nix/vm-test.nix`, `checks.x86_64-linux.nixos-module`). One machine imports `nixosModules.default` and sets `enable`, `baseHost` and a `secretFile` of mode `0400` under `/etc`. No container runtime is involved. The test asserts:
- `/api/health` answers `{"ok": true}`;
- `systemctl show -p Environment` contains neither the secret nor `BETTER_AUTH_SECRET`;
- a deck created from the `team-check-in` template is found by `GET /api/join/:code`;
- `omul.sqlite` and `auth.sqlite` exist in `/var/lib/omul`;
- after `systemctl restart omul.service` the join code and `GET /api/presentations/:id` still return the deck, and the edit token returned at creation still starts it.

**Bun version.** The pinned nixpkgs (`e06158e5`) carries Bun 1.2.13, while `.mise.toml` resolves `bun = "1"` to the latest 1.x. Bun 1.2.13 builds the client and the server and runs them: Vite prints a warning that it wants Node 20.19 or 22.12, because Bun 1.2.13 reports Node 22.6.0, and builds anyway. So the `nixpkgs` input was not updated.
