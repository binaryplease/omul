## Description

A theme or a workspace carries a logo image, rendered on the participant-facing surfaces in place of or beside the default mark.

## Updates

- 2026-08-08 — Custom logo shipped, carried by the deck's theming block (this codebase has no workspace, so the theme is the carrier that exists): themeLogoUrl + themeLogoAlt on the deck, following the existing image-URL pattern — nothing is uploaded, stored or proxied. deckLogoFor() in server/schemas.ts is the single read site and allowlists the scheme (http(s) or root-relative resolve; javascript:, data:, file:, protocol-relative and unparseable resolve to null), so an unusable URL falls back to the product's own mark rather than reaching an attribute; the alt falls back to the deck title, then to decorative. <DeckMark> renders it on the participant-facing surfaces — the join screen, the waiting and ended screens, above the live participant slide, and on the instruction slide's join screen the room reads the code off — in place of the default pulse dot where there is one and beside the content where there is not. Authored in the editor with a live preview of the resolved mark; a guard in scripts/guard-frontend-conventions.ts fails the build on a surface reading themeLogoUrl raw. Tests: server/theme.schemas.test.ts, server/theme.integration.test.ts.
