## Description

A pin slide can carry a target region. After the reveal each pin is reported as inside or outside it; the region is withheld from non-editors before the reveal.

## Updates

- 2026-08-06 — Optional correct area as an integer rectangle (PinAreaSchema, nullable default null) authored by dragging a box across the picture or typing its four corners; isPinInArea is inclusive on every edge, isUsablePinArea refuses one running off the image. Results report correctArea/correctCount/correctShare, the participant is told whether their own pin hit the target, and all three are withheld together from the room until the slide's results visibility reveals them (stripped from the deck payload by withAudienceSolutions, never sent under 'private').
- 2026-08-06 — Review fix pass (NST8288): the reveal now reaches a live participant — the deck is re-read when the reveal set moves (session slice refreshDeckSlides + ParticipantPage effect), so the target outline and the participant's own 'in the target area' verdict appear without a reload and are re-stripped when the slide is hidden again. Enabling a correct area also authors resultsVisibility 'on-click' (withPinAreaEnabled), so an organizer no longer ships the answer visible while participants aim; explicit Instant stays available and now warns. Picker fixes: a cancelled pointer drag no longer keeps resizing the target, a click on the far right/bottom edge yields a saveable area, and the drawn overlay now matches isPinInArea's inclusive far edge.
