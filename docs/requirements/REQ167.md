## Description

The surfaces that identify the product to a visitor present the drawn `omul` wordmark and its ring signet in place of the working name set as a lowercase word and the bar-chart icon they carry today: the mark in the home header, the browser tab's icon and document title, and any tile or avatar rendering of the product. The wordmark is set in ink `#09090B` on paper `#FAFAFA` and its inverse form swaps the two, so one of the pair reads correctly in each scheme; the mark is never drawn in the accent, which belongs to the interface. Below roughly 56 px of wordmark width the closed-ring signet takes over, and the closed ring is also the form used for icon, tile and avatar. The wordmark stands alone: no expansion or gloss of the name appears on a user-facing surface. Done when: loading the application in either scheme shows the drawn wordmark in the home header and the ring signet as the tab icon, the document title names the product as `omul`, no user-facing surface still shows the old bar-chart icon or the working name, and the repo's gate and test task (both named in `AGENTS.md`) stay green.

## Notes

Current behaviour: there is no drawn mark anywhere in the tree. What identifies the product is three things — `src/pages/HomePage.tsx:174-179`, a 3px accent dot beside the working name set as a lowercase word in the mono face; `src/index.html:8`, a document title carrying that name and a tagline; and `public/favicon.svg`, three orange bars with three gold dots on `#0D0D0D`, which shares neither its geometry nor its palette with the wordmark.

The mark files are drawn, final and supplied with this work — the wordmark, its inverse form, a closed-ring signet, an open-ring signet, and raster exports. Carrying them into the tree and wiring them to the surfaces above is the work; redrawing them is not, and the specimen sheet's construction measures describe the mark rather than any UI dimension.

The ink and paper values are the same two the neutral direction of REQ166 uses for text and ground, so the mark and the chrome share them rather than each holding a copy. The warm pair of the first wordmark draft is superseded and must not appear.

Not in scope, and why: the **repository identifier** — `package.json`'s `name` field, the theme key in `src/components/ui/Theme.tsx`, the deck-export file extension in `src/pages/HomePage.tsx`, and the remote itself. The outward name and the identifier in the repository are two separate operations, and none of those four is a surface a visitor sees; they belong to a rename requirement of their own, which is REQ174 / REQ175 / REQ176. Also excluded: the open-ring signet as a live UI state marking a running vote — it exists as a file and is named here so it is not mistaken for a missing asset, but whether it earns a place in the interface is undecided.
