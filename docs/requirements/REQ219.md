## Description

As an organizer writing a quiz, I want the editor to tell me when a quiz question has no correct answer, so that I do not run a question on which every participant is told they were wrong. This repairs REQ013 (marking options correct) and REQ054/REQ055 (the select and typed quiz questions), which let such a slide reach the room without a word.

A quiz slide has no answer key when it is answered by selecting and no option is marked correct, or when it is answered by typing and no accepted answer survives the grader's normalization. The editor says so in three places, in one wording: in the slide's own settings (with what to do about it in that answer mode), on the slide's thumbnail in the slide list, and in a prompt when the presenter starts or restarts the deck, which names every such slide by number and question in deck order. It is a warning, not a block: such a draft saves, and the prompt offers "Start anyway" beside "Cancel". Every one of the three is reachable without sight or a pointer: the settings warning is a polite status region, the thumbnail carries the words inside its button's accessible name, and the go-live prompt is a modal dialog named by its title, described by its message, focused on Cancel when it opens, closed by Escape, and handing focus back to Start when it closes. A deck whose quiz questions all have a key, including every catalog template, starts without the prompt.

## Notes

Defect, **internal**: found by a UI test pass of the quiz feature on `f3bd62e` (major M4). Add slide → Quiz, question and options, no option marked, Create, go live: no warning anywhere, and a participant choosing "Wien" read "Leider falsch · +0". The protocol predicted the same for a typed quiz with no accepted answer from `matchesQuizAnswer`; on the tree before this fix the typed case already showed a settings warning ("No accepted answer yet"), but nothing on the thumbnail or at go-live, and the select case showed nothing at all.

**What closes it.**

- `server/schemas.ts`: `quizHasAnswerKey(slide)` reads the answer mode, then `correctQuizOptionIds` or `acceptedQuizAnswers` — the same functions the grader reads, so "has a solution" cannot mean one thing where it is warned about and another where it is scored. Any other slide type reads `true`. `quizSlidesWithoutAnswerKey(slides)` lists the positions.
- `src/components/QuizAnswerKeyWarning.tsx`: the one wording (`QUIZ_NO_ANSWER_KEY_WARNING`), the per-mode remedy, the settings warning (`role="status"`, always in the tree so it is heard as it comes and goes), and `quizAnswerKeyGoLiveWarning(slides)`, which builds the prompt's title and message.
- `src/components/SlideEditor.tsx`: the quiz's Answers group renders the warning in both modes; it replaces the typed-only "No accepted answer yet" line.
- `src/components/SlideThumbnail.tsx`: a warning icon in the meta row, the words in a `sr-only` span inside the button, and in its tooltip.
- `src/pages/PresenterPage.tsx`: Start (and Restart) opens the prompt when the list is not empty; "Start anyway" goes live.
- `src/components/ui/ConfirmModal.tsx`: the panel is `role="dialog"` with `aria-modal`, `aria-labelledby`/`aria-describedby`, focus on Cancel while open and back on the opener after, Escape cancels. Shared, so the Reset and edit-link prompts gain the same.

**Why a prompt and not a block.** A quiz with no key is far more often an unfinished draft than a mistake, and a presenter may run one on purpose. The task that raised this asked for a warning, not a hard block, with drafts staying saveable.

**Pattern followed.** The brief pointed at a go-live prompt that names slides starting closed and attributed it to REQ193. REQ193 in this tree is the fork-safe CI requirement, and no such prompt exists here, so this one was built on the existing `ConfirmModal`.
