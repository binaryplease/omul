## Description

As a participant, I want a quiz question's countdown to start only once the room can see the question, so that a presenter who clicked through the deck while preparing does not leave me a question that is already running or already over. This repairs REQ226 (a timed quiz on screen at go-live waits for the presenter) and REQ057 (the quiz question window). Both opened question windows on draft decks without anybody noticing.

- **Only a live deck opens a question on navigation.** `setActiveSlide` stamps `slideStartedAt` only when the deck's status is `live`. While the deck is a draft, or ended, the owner can still move through the slide list, but no window opens and no `slide.started` frame goes out.
- **Going live from a draft starts with no question opened.** On a presenter-paced deck, `startPresentation` drops any `slideStartedAt` stamps a draft still carries before it applies the go-live rule from REQ226. This covers decks stored before the rule above existed. Survey drafts keep their stamps, because they collect answers in draft (REQ003).
- **The phone states the right reason.** A question that waits for its timer (REQ226) but that the presenter has also closed (REQ111) shows the closed reason, not "Waiting for the presenter to start this question". Starting the timer does not reopen the slide.
- **A double click on Start timer is one start.** The presenter page ignores a second timer click while the first request is still in flight.

## Notes

Defect, **internal**: found by the code review of the REQ226 change. The presenter page's slide list navigates the deck in every status. The Previous/Next buttons and the arrow keys only work while live. `setActiveSlide` did not check the status, so clicking slide 2 and then slide 1 on a draft stamped slide 1. `startPresentation` then left that stamp standing on the waiting question. After a 30 s wait in the draft, the question showed "Time's up" at go-live, with no "Start timer". Any later quiz visited during the draft had expired by the time the live deck reached it.

Reproduced on the tree before the fix. The integration tests "paging through a draft opens nothing", "a question visited in a draft opens fresh" and "going live from a draft drops a stamp left by earlier draft navigation" fail on it.

Deliberately not changed: a **live survey** deck still stamps on presenter navigation, as it always has. Survey participants navigate on their own, so the presenter's slide list is rarely used there. Making survey decks never stamp is a separate decision about REQ003.
