## Description

A slide type rendering the deck's accumulated quiz standings. The recount is coalesced rather than run once per arriving answer.

## Updates

- 2026-08-06 — Leaderboard slide shipped: new non-interactive 'leaderboard' slide type whose results payload is the deck's standings across every quiz question (rank, anonymous entryId/label, totalPoints, correctCount, answeredCount), served on the existing results endpoint and re-broadcast after every quiz answer. Rows are named by a one-way SHA-256 handle scoped per presentation — no participant id reaches the public board and no nickname flow was invented; a participant finds their own row and learns their place (including below the projected cut) from their own scorecard, which now carries entryId/label/rank/rankedCount. Ranks are standard competition ranks with ties sharing a place; leaderboardSize (1-20, default 5) caps the shown rows, never the ranking. Surfaces: editor panel + preview + rail gist, presenter shared screen, participant phone with their own row highlighted (i18n across all 7 languages). Tests: server/leaderboard.schemas.test.ts, server/leaderboard.integration.test.ts, src/components/Leaderboard.test.ts, plus a ws broadcast test.
- 2026-08-07 — Touched by the REQ147 fix: rankQuizDeck kept its own per-participant de-duplication, which was the same rule the room's tally beside it did not have — so the board and the bars reported the same room differently when a participant held two answers. The de-duplication now lives once in finalQuizAnswers, upstream of every read of a quiz slide's votes, and rankQuizDeck composes it instead of restating it.
- 2026-08-07 — Standings recount taken off the per-answer hot path. broadcastStandings re-read and re-scored every quiz slide in the deck and broadcast to every socket once per individual answer, so the cost of a question scaled with the size of the room: measured on a 20-question deck with one leaderboard, 300 answers arriving together cost 300 deck recounts (21 store queries each = 6300) and 90000 board socket writes. The recount is now folded through a new coalescer (server/coalesce.ts, ADR-0007 factory, ADR-0032 own module): the first caller runs it immediately and awaits it, everything arriving inside the next 500ms window is merged into one trailing run. Same measurement after: 2 recounts (42 queries) and 600 board socket writes, with the vote burst's wall clock 931ms to 531ms. Cost now scales with a question's duration rather than the room's size. All three things that move a board still reach it — an answer landing, an edit to what counts as correct, a restarted question window — because no trigger is dropped, only merged, and the work re-reads the store at run time so the last change is always in the last run; verified live against a running server on all three paths. It also removes an ordering bug the direct call had: two answers landing together put two recounts in flight over the same socket and the one that started first could finish last, overwriting a fresher board with a staler one; runs on one deck can no longer overlap. broadcastStandings also stopped re-fetching the deck per leaderboard slide, since it already holds it. Covered by server/coalesce.test.ts (11 cases, injected timer) and a ws.integration.test.ts case verified failing against the un-coalesced call.
