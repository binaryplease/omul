## Description

As a participant whose quiz answer is still on its way when the presenter clicks "Close submissions", I want the line under the answer control to say the question was closed, so that I know what happened to my answer and a screen reader tells me, the same way it does when the answer is refused for any other reason.

REQ232 puts a stated refusal in the answer status line that REQ221 made a polite live region, worded from the deck's language. The line drops a refusal once the question is over, so the participant reads the result like anybody who did not answer in time. Closing a quiz ends it (REQ216), and the close reaches the phone as a broadcast before the refused answer does. So a `participation-closed` refusal was dropped the moment it arrived, and the line went from "Sending…" to empty. The reason stood only in the closed banner above the question, which a screen reader is not reliably told about.

- **A closed quiz question is a lock reason of its own.** While a quiz slide is closed and this participant has no answer on record, the answer status line reads the participation wording ("The presenter has closed this question", in the deck's language). An answer refused as `participation-closed` lands on that line, as `quiz-not-started`, `quiz-window-closed` and `quiz-already-answered` each land on the lock reason they share wording with.
- **Order.** Waiting to start (only while the slide is open, REQ227), then "your answer is final", then closed, then "time is over". The countdown goes on after a close, so a closed question keeps saying closed after its countdown runs out.
- **The refused answer is presented as for the other codes**: no card is drawn as chosen, and a typed answer stays in its locked field.
- **Unchanged:** the vote route, its refusal codes and window rules; the closed banner above the question; plain choice slides, which have no quiz lock and already showed the refusal.

## Notes

Defect, **internal**: found in Re-Test D (D2) on a select and a typed question, with the vote delayed in the browser and "Close submissions" clicked while it was in flight.

- **Client:** `quizLockReason` in `src/components/ParticipantSlideView.tsx` gains the closed branch. The cards and the typed field read the same value for their `title`, so the closed control also explains itself on hover and focus (ADR-0025).
- **Tests:** `src/components/ParticipantSlideView.test.ts`, in "a refused quiz answer keeps the participant on the slide (REQ232)". For `quiz-not-started`, `quiz-window-closed` and `participation-closed`, select and typed, the phone in the state the refusal reports is rendered in German, and the line under the control must read that refusal's own wording. `quiz-already-answered` is left out because its state comes from the scorecard re-read, an effect a static render does not run. A further test pins "closed" over "time is over" after the countdown. The `participation-closed` cases and that test fail on the tree before the change, where the line is empty.
