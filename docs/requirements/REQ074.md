## Description

A deck carries comment threads anchored to individual slides, readable and writable by the accounts it is shared with and never visible to participants.

## Updates

- 2026-08-13 — Slide comment threads shipped end to end: a slideComments collection and services/slide-comments.ts, three account-gated routes (read for any grant or the owner, write for comment/edit, author-only delete) resolved by resolveDeckAccountAccess so the edit token and the legacy grandfather open nothing; SlideComments.tsx worn by the editor's canvas strip and the presenter's panel — the door a view/comment grantee reaches; asserted absent from every participant-facing payload and the slide.changed frame
- 2026-08-14 — Defect found in review and split out as REQ160: the composer held one loose draft that no slide change reset, and both call sites closed over the selected slide at submit time, so a half-written comment could post to whichever slide was selected when Comment was pressed
- 2026-08-14 — Review fix: GET /presentations/:id now reports commentAccess — the caller's account standing, resolved by resolveDeckAccountAccess — beside accessLevel, and both comment surfaces gate on it (PresenterPage chip/panel, CreatePage strip; the read is also held back until the standing is known). Previously the client gated on accessLevel, which reads 'edit' for the anonymous edit-token holder the comment routes refuse, so the default no-account flow fired a guaranteed-401 comments fetch on every load and drew an enabled chip claiming a count. Integration tests assert the pair (accessLevel 'edit' / commentAccess null for the token holder).
