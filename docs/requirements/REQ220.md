## Description

As an organizer, I want a slide I just added to save as it is when it asks the room nothing, and I want a refused save to tell me which slide it means, so that I am not stopped by a rule that does not apply and then left to search the deck for its cause. This repairs REQ059 (the leaderboard slide) against the editor's save rules, and REQ153 (authoring on the canvas), whose placeholder promised the leaderboard heading the room would show.

The editor requires a question only on slides that collect answers (`slideRequiresQuestion`). A leaderboard, like every content slide (text, image, video, embedded deck, How to Join), saves with an empty heading; the room draws the board's own title in its place. When the editor does refuse a save, the message starts with the slide's rail number ("Slide 3: …"), the slide is selected, its thumbnail is scrolled into view, and the banner is announced as an alert. The option rows a typed quiz question never shows are not checked for text.

## Notes

Defect, **internal**: found by a UI test pass of the quiz feature on `f3bd62e` (minor m2). Add slide → Leaderboard → Save Changes failed with "All slides need a question". The heading field showed "Leaderboard" only as a placeholder, so it looked filled. The message did not name or select the slide, and a leaderboard has no question.

**What was wrong.** `CreatePage.handleSubmit` required a question on every slide that was not a content slide. A leaderboard is neither content nor a question (the schema's own docs use it as the proof that the two sets differ), so it was caught. Every refusal message was also generic ("All options need text"), and only the selection hinted at which slide it meant.

**What closes it.**

- `server/schemas.ts`: `slideRequiresQuestion(type)`, true exactly for the slide types that collect answers.
- `src/slide-save-refusal.ts`: the editor's save rules, moved out of `CreatePage.handleSubmit` unchanged apart from the two fixes, as one pure function returning `{ slideIndex, message }` with the message prefixed `Slide N: `. The option-text rule asks `isChoiceShapedSlide`, so a quiz switched to typed answers is not refused over the blank options it keeps but never shows (found while testing this; a fresh quiz switched straight to Type could not be saved).
- `src/pages/CreatePage.tsx`: selects the slide the refusal names; the error banner is `role="alert"`.
- `src/components/SlideThumbnail.tsx`: the selected thumbnail scrolls itself into view (`block: "nearest"`).
