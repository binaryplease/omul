## Description

The presenter can blank the shared audience view without leaving the slide, closing participation or losing collected answers.

## Updates

- 2026-08-13 — Shipped. audienceBlanked on the presentation (public, default false), moved by POST /presentations/:id/blank {blanked} under owner-or-edit-token and broadcast as presentation.blanked so a second browser on the projector blanks too. What goes dark is the shared screen alone — the projected slide, its background and the reactions over it — while each participant's phone keeps its question and its control, which is what makes 'without closing participation' mean anything. The endpoint writes one boolean: status, activeSlideIndex, closedSlideIds, slideStartedAt and every stored vote are left exactly where they were, asserted over HTTP. Deck-level and sticky across navigation, so the presenter can line the next slide up behind the curtain — which keeps the slide navigation for that reason — and the curtain states itself rather than going dark, since an unexplained dark projector reads as a lost signal. Reset brings the screen back.
- 2026-08-14 — Review fix (NST9011, finding 1): blanking covered only the centre column of the presenter page, so the shared screen kept its rail of slide questions, the deck title and join code in the header, and any open Q&A/chat panel — under a curtain reading 'The room sees nothing on the shared screen'. That page is the product's only shared screen and the presenter's laptop is the projector, so all of it was in front of the room. The blanked screen is now an early return in PresenterPage: on that path there is no deck-bearing JSX at all, only the curtain. sharedScreenView() in LiveRoom.tsx is the named decision, with tests. Verified in a browser: no slide title, deck title, join code or panel content on the blanked screen.
