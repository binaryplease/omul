## Description

As the person who has to sign off that this tree is safe to publish, I want a full-history secret scan of the repository to return no findings, so that the one piece of evidence the publication gate rests on is a clean run rather than a run with a finding somebody has to be talked out of.

## Notes

Raised by a publication readiness check, **internal**. Nothing is disclosed by this finding and there is no live credential in it; what is broken is the evidence, not the system.

**What changed.** Every full-history scan of this repository up to 2026-08-27 returned no leaks. The scan on 2026-08-28 returns one, and it is the first in this repository's life:

- `server/auth-secret.test.ts:43`, rule `generic-api-key`, entropy 5.41, introduced 2026-08-28 in the commit that landed REQ171's fail-closed auth-secret gate.

It is a `const` holding a 44-character base64 string, commented as *a secret shaped like what the crash message tells an operator to generate*, and it exists so two cases can assert that an exported `BETTER_AUTH_SECRET` wins over the development default and is trimmed of surrounding whitespace. It appears in exactly one file and one commit; nothing else in the tree or in any ref contains it.

**Why a test fixture still matters here.** Two separate reasons, and the second is the one that costs.

1. *It cannot be told apart from the real thing by the tool, and barely by a reader.* The scanner reports a high-entropy credential in a file that resolves auth secrets. Whoever reads the gate report has to open the file, follow the test, and satisfy themselves that the string authenticates nothing — which is exactly the judgment call a scan exists to remove. A fixture that trips the scanner has spent the scanner's value.

2. *It makes every future sweep dirty.* The publication gate's evidence is a clean scan on a fresh clone. From here, that scan reports `leaks found: 1` forever, on this repository and on any tree exported from it, because the finding is in the file and not only in history. A gate whose evidence is "one finding, but it is fine" is a gate that trains its reader to wave findings through.

**Not a rotation item.** The value was authored on 2026-08-28 alongside the test that uses it, it is used only as an input to `resolveAuthSecret()` inside that suite, and no deployment reads it — the live instance takes its secret from the deployment's own secret delivery. The author of that commit should confirm it was typed rather than copied; if it was copied from anywhere real, the deployed `BETTER_AUTH_SECRET` is rotated and this stops being a hygiene item.

**The shape of the fix.** Keep both assertions and make the fixture obviously synthetic: a value with the same *shape* — 44 characters, base64 alphabet, trailing `=` — and none of the entropy, built from a repeated or otherwise patterned run of characters, or composed at runtime from a literal the scanner does not read as a secret. A scanner allowlist entry is the wrong instrument: it suppresses the rule for the file, which is where the next real one would appear.

**Done when.** `nix run nixpkgs#gitleaks -- git . --log-opts="--all" --redact` reports no leaks over the full history; `server/auth-secret.test.ts` still asserts that an exported secret wins over the development default and that surrounding whitespace is trimmed; no scanner allowlist or ignore file has been added; and `mise run check` and `mise run test` stay green.
