## Description

As the owner of a repository headed for publication, I want a `LICENSE` file, an SPDX identifier in `package.json`, and an enumerated third-party license position across the *whole tree that ships* — including the vendored source tree — so that the license stamped on the public repository is a claim that is true rather than one that cannot be withdrawn once it is wrong.

## Notes

Raised by a publication readiness check, **internal** — nothing is disclosed by this finding on its own; it is a correctness problem in a claim the repository has not yet made.

**What is absent today.** There is no `LICENSE`, no `COPYING`, no `NOTICE`. `package.json` carries `"private": true` and no `license` field. GitHub's community profile reports `license: null` and a health percentage of 28. `AGENTS.md` states the repository is headed for publication and the design document calls the product open-source, so the intent is on record while the instrument is not.

**Why this is P0 and not paperwork.** Stamping an SPDX identifier onto a tree that contains third-party code under an incompatible or unstated license is a false license claim, and publication is one-way — the claim is cloned, mirrored and indexed within minutes of the flip, and withdrawing it later does not reach the copies. The identifier must therefore be applied *after* the tree it covers has been enumerated, not before.

**The vendored tree is the open question.** A lockfile does not mention it, so it appears in no dependency audit:

- `vendor/binp-docstore` — `name: binp-docstore`, `version: 0.0.0`, **no `license` field at all**, no `LICENSE` file. It is a first-party library by every other sign, and it is the project's entire storage layer (`bunfig.toml`, `package.json` `file:./vendor/binp-docstore`). The canonical upstream has since been licensed MIT and renamed, so this is a stale copy of licensed code rather than unlicensed code — but what ships is what the tree holds, and the tree holds no grant.

There was a second vendored tree, `tools/inspector`, a development-only element picker vendored as a `file:` dependency. It was removed from the repository on 2026-08-28 rather than given the MIT notice its own manifest promised — see the update log.

**What else the claim has to cover.** The installed dependency set is licence-clean by the usual reading — 170 MIT, 15 ISC, 11 Apache-2.0, 4 BSD-2-Clause, 3 BSD-3-Clause, 3 MPL-2.0, 2 OFL-1.1 (the bundled sans and mono webfonts, which carry an attribution obligation of their own — Figtree and DM Mono today; the sans was Sora when this was first measured, and REQ178 swapped it), 1 Unlicense, 1 0BSD, and three dual/compound grants. MPL-2.0 is file-level copyleft and compatible with permissive distribution; it is named here so the enumeration is complete, not because it blocks anything. The fonts under OFL-1.1 ship in the built client, which is where an attribution file has to reach.

**Boundary.** This requirement does not choose the license — that is the owner's decision with the legal advisor, and an absent decision does not default to MIT. It requires that whichever identifier is chosen is applied to a tree whose contents have been enumerated first, with the copyright year taken as a fact rather than guessed, and with any `NOTICE`/attribution the chosen license or the bundled assets require.

**Done when.** `LICENSE` present at the root; SPDX identifier in `package.json` with `private` removed or deliberately retained with a stated reason; `vendor/binp-docstore` carries an explicit grant; bundled fonts attributed; the license named in the README and reported present by `gh api repos/<owner>/<repo>/community/profile`.
