## Description

A quiz slide where the participant types the answer, matched against an authored list of accepted answers after normalization. Same one-final-answer rule and same scoring as the option form; the answer key is withheld from non-editors.

## Updates

- 2026-08-06 — Quiz competition type-answer shipped: a quiz slide carries a quizAnswerMode (select | type) rather than a second slide type, so a typed question inherits REQ054/REQ056/REQ057's machinery unchanged — one final answer, the same presenter-opened window and refusal reasons, the same correctness-plus-speed score, the same results scoring block and /scorecard endpoint. Typed solutions are authored as quizAnswers[] (up to QUIZ_ANSWER_LIMIT = 10). Matching rule chosen: exact match after normalization (normalizeQuizAnswer — folds case, combining diacritics, internal whitespace runs and surrounding punctuation/quotes; folds nothing else — no reordering, no abbreviation, no edit distance, and punctuation inside the answer stays, so C++ is not C). Deliberately not fuzzy: a scored competition must never award a wrong answer, and distance matching cannot have that property on quiz-sized answers (1997 and 1987 are one edit apart) — that failure is invisible to the organizer, while a refused typo is visible and fixable by adding the spelling. Variants no normalization could fairly fold (USA / United States) are admitted by the organizer's own list. A question with no accepted answer scores nobody, as a choice slide with no marked option does. The answer key is withheld from non-editors on the existing gate — quizAnswers empties to [], leftover options empty too (a select-to-type switch keeps them, and the correct one is spelled out among them), and the room's typed answers are withheld with it, since on this question type the modal answer is the answer. Results gain answerMode plus a typedAnswers block (entries grouped by the same normalization, labelled with the first spelling that arrived); the scorecard gains answerMode and answer beside optionId, both keys always emitted (ADR-0024). Client: answer-mode picker and accepted-answers editor with a no-solution warning and a duplicate hint, typed preview and rail gist, participant text field under the shared countdown/lock/verdict (QuizVerdict factored out and worn by both modes), typed results renderer, 2 new i18n keys across all 7 languages. Tests in server/quiz-typed.schemas.test.ts + server/quiz-typed.integration.test.ts; docs/api.md and docs/frontend.md updated.
- 2026-08-06 — Review fix pass (NST8270): the results tally of a typed question now carries no options at all — a question switched from select keeps its authored options, so the tally was shipping the correct option's text to every non-editor and re-broadcasting it to the room after each answer, on a question whose point is that there is nothing to read off. Same rule withAudienceSolutions already applied to the deck; docs/api.md had already documented the tally as empty. Matching rule narrowed and corrected: the accent fold is now the three Combining Diacritical Marks blocks rather than \p{M}. Every combining mark in Unicode was too wide — in Devanagari, Thai, Hebrew and Arabic those marks are letters, not accents, so \p{M} folded कील onto कल and ที่ onto ท, awarding full marks for a different word, which is the invisible failure the rule exists to prevent. Latin folding (Muller answers Müller) is unchanged; a non-Latin accent is now simply not folded, which is the visible, organizer-fixable direction. Also: respondentCount now drops a stale select vote on a converted question through the same isStandingQuizAnswer gate the score and the typed tally use, so one payload cannot report 1 respondent beside 0 answers; and the typed answer field carries maxLength=VOTE_VALUE_MAX_LENGTH (500, exported from schemas and composed by both VoteSchema and the input) so the cap arrives as a dead key rather than a raw Elysia validation failure. Regression tests added for all four.
- 2026-08-07 — Touched by the REQ147 fix: tallyTypedQuizAnswers counted rows, so a participant holding two standing answers appeared twice across the groups the block exists to summarize. It now counts over finalQuizAnswers, making a group's count people rather than rows — the same unit respondentCount and the scoring block report. Covered by a case in server/quiz-typed.integration.test.ts.
