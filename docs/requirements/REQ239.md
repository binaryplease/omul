## Description

As an organizer who builds a deck with a screen reader, I want the language select in the presentation settings to announce what it sets when it takes focus, so that I can choose the audience's language without guessing what an unnamed combobox is for.

The deck's audience language (REQ084) is chosen in Presentation settings → Language, from a select under the caption "Audience language". The caption is drawn but not bound to the select, so assistive technology announces a combobox with no name (WCAG 2.2 SC 4.1.2 Name, Role, Value; SC 1.3.1 Info and Relationships).

- **The select's accessible name** is "Audience language", the caption's own words, held in one constant so the visible and the announced name cannot drift apart.
- **Built like the quiz time-limit box (REQ231):** the name sits on the control as `aria-label`. The shared `Field` caption heads its control rather than binding to it, and is not changed here.
- **Unchanged:** the select's options, its value handling, and every other field in the presentation settings.

## Notes

Defect, **internal**: Re-Test D, D3. An accessibility snapshot read the select as an unnamed `combobox`, with no `id` label, `aria-label` or `aria-labelledby` and no wrapping `<label>`.

Out of scope: other unnamed controls in the app.

- **Client:** `AudienceLanguageField` in `src/pages/CreatePage.tsx` is the select and its caption, lifted out of `DeckSettings` unchanged except for `aria-label={AUDIENCE_LANGUAGE_LABEL}`; `DeckSettings` composes it in its Language section.
- **Server, participant view, `cli/`:** not touched.
- **Tests:** `src/pages/CreatePage.test.ts` renders the field and asserts the select's accessible name — read by `aria-labelledby`, `aria-label` or `<label for>`, in that order — equals the caption's text, for two languages. Both fail when the `aria-label` is absent.
