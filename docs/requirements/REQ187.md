## Description

As an operator or contributor who sets `OMUL_AUTH_DB=:memory:` or `OMUL_ADMIN_DB=:memory:` for a throwaway run, I want that to give me an ephemeral in-memory SQLite database, the same way `DATABASE_PATH=:memory:` and `OMUL_FEEDBACK_DB=:memory:` already do, so that a probe or a test never leaves a real database file named `:memory:` in whatever directory it was started from.

## Notes

**The defect.** `server/accounts.ts` and `server/admin-events.ts` each built their path as `configured ? resolve(configured) : <docstore sibling>`. Node's `resolve(":memory:")` is `<cwd>/:memory:`, a path rather than SQLite's in-memory sentinel, so bun:sqlite created a real (empty, 4096-byte) database file by that name in the working directory. Only the case where the *docstore* was `:memory:` was passed through; an explicit `:memory:` in the module's own variable was not. `feedbackDbPath()` in `server/feedback-store.ts` already handled both cases and was the precedent.

**How it surfaced.** A review probe run from the repository root with `DATABASE_PATH=:memory: OMUL_AUTH_DB=:memory:` left a `:memory:` file in the root. The session runner's commit hook staged it and then refused to commit a stray binary into this published tree, leaving every later session on a dirty index.

**The fix.** One resolution rule, `siblingDbPath(configured, filename)` in `server/sibling-db-path.ts`: an explicit `:memory:` passes through, any other configured value is resolved, and with nothing configured the file is a sibling of the docstore — or `:memory:` when the docstore is. `authDbPath()` (accounts) and `adminDbPath()` (admin events) compose it. Unset and real-path behaviour is unchanged. `server/store-path.ts` and `feedbackDbPath()` are deliberately untouched.

**Done when.** An explicit `:memory:` for either variable resolves to `:memory:`; a test pins that for both and fails on the old resolution; no `:memory:` file exists in the tree after `mise run test`.

## Updates

- 2026-10-09 — Fixed. server/sibling-db-path.ts holds the one rule (explicit :memory: passes through; any other configured value is resolved; unset gives a docstore sibling, or :memory: when the docstore is). server/accounts.ts exports authDbPath() and server/admin-events.ts exports adminDbPath(), both composing it; unset and real-path behaviour unchanged. Pinned by a new case in server/accounts.test.ts (OMUL_AUTH_DB) and server/admin-events.test.ts (OMUL_ADMIN_DB, plus the unset sibling and :memory: docstore cases); against the old resolution both fail with Received "<cwd>/:memory:". The stray empty :memory: SQLite file is removed from the root and the index. docs/deployment.md and .env.example left as they were: the nearest analogue, OMUL_FEEDBACK_DB, does not document :memory: either. mise run test 2647 pass / 0 fail across 147 files, with no :memory: file left anywhere in the tree afterwards.
