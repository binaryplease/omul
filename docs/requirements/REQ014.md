## Description

A multiple-choice slide can accept more than one option per participant. The tally then reports a selection rate per option rather than one vote per participant.

## Updates

- 2026-07-28 — Participants can select several options on a multiple-choice slide. New per-slide mcMaxSelections (1 single choice, 0 unlimited, n capped) resolved through the shared maxSelectionsFor(), which falls back to the legacy allowMultiple flag so slides authored earlier behave exactly as before. Enforced server-side in submitVote: one vote row per selected option, re-submitting an option deselects it, a submission past the cap is rejected with 400, and an unknown option id is rejected rather than burning a slot. The participant UI offers checkbox-style cards and disables — never hides — what would exceed the cap (ADR-0025). Aggregation now reports respondentCount (people) alongside totalVotes (selections); percentages divide by the head count, so shares stay stable as participants tick more boxes and deliberately sum past 100%, with a footnote on the results saying so. Pie/donut slice geometry still divides by totalVotes so the disc closes. Covered by server/mc-settings.integration.test.ts.
