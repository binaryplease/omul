## Description

The address the server listens on is set by an explicit environment variable, and with the variable unset the server listens on loopback only, in development and production alike. The container image sets the variable to `0.0.0.0`, so a container keeps answering through its published port.

Done when each of these holds:

- With the variable unset, the server listens on `127.0.0.1` whether `NODE_ENV` is `production` or not, and a connection to the machine's other addresses on `PORT` is refused.
- With the variable set, the server listens on the address it names, and the startup log line names that address.
- `NODE_ENV` no longer decides the bind address.
- The `Dockerfile` sets the variable to `0.0.0.0`, and a container built from it answers on its published port as it does today.
- The variable is documented in the `## Environment variables` list of `docs/deployment.md`, with its loopback default and the image's `0.0.0.0` value.

## Notes

**Before this.** `server/index.ts:272` sets `const HOSTNAME = isDev ? "127.0.0.1" : "0.0.0.0";`, and `isDev` is `process.env.NODE_ENV !== "production"` (`server/index.ts:34`). The comment above line 272 gives the reason: inside the Docker container a loopback bind makes the port unreachable through Docker's port mapping. The bind address therefore follows the build mode. A production build started outside a container, under systemd for example, listens on every interface of the host. It is then reachable directly, around the reverse proxy that the rate-limit keying (`OMUL_TRUST_PROXY`, REQ145) and TLS assume is in front of it.

**Out of scope.** The variable's name, how an invalid value is handled and whether an IPv6 address is accepted are the builder's to choose. Changing `PORT` or the reverse-proxy guidance in `docs/deployment.md` is not part of this requirement.

**Follow-up once built.** The Docker-free self-hosting guide (REQ249, `docs/self-hosting-without-docker.md`) confines its systemd unit with `IPAddressDeny=any` and `IPAddressAllow=localhost`. Those lines keep the unit's 0.0.0.0 listener off the network, and they also block outbound mail and deck generation (REQ007). With a loopback default the unit no longer needs them, and a later change to that guide can drop them.
