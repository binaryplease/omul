## Description

On a participant-facing surface where no organizer logo is available, the product identifies itself with the closed-ring signet REQ167 settled on as its small-size mark, drawn in the mark's own ink-and-paper pair rather than in the accent, in place of the accent pulse dot those surfaces show today. The organizer-logo path is untouched: a deck that carries a usable logo still shows it, and the product's mark appears only where REQ136 already puts a fallback. Done when: the join screen and a participant's screens for a deck with no logo show the ring signet where the accent dot is drawn today, legible against the canvas it sits on in both colour schemes, and the repo's gate and test task (both named in `AGENTS.md`) stay green.

## Notes

Current behaviour: `DeckMark` (`src/components/DeckTheme.tsx:781-829`) renders the organizer's logo when `deckLogoFor()` resolves one, and otherwise a 12–20px `rounded-full glow-pulse` span filled with `bg-accent`. The module's own header names what that dot is — "the product's pulse dot" (`src/components/DeckTheme.tsx:58-60`) — and it is the same dot REQ167 removed from the home header when it put the drawn wordmark there. It survives here because REQ167 covered the surfaces that identify the product to a *visitor*; these are the ones that identify it to a participant. Where it draws: the join screen unconditionally, since that screen knows no deck yet and passes `deck={null}` (`src/pages/JoinPage.tsx:162`), and the participant's name screen and ended screen for any deck without a logo (`src/pages/ParticipantPage.tsx:430,471`).

REQ167 already fixed the form this needs, so nothing here is a new drawing decision: below roughly 56px of wordmark width the closed ring takes over, the closed ring is the form used for icon, tile and avatar, and the mark is never drawn in the accent, which belongs to the interface. `BrandMark` is where those live.

The legibility clause in the done-when is there because a deck scope changes the canvas under the mark: `--color-mark` is declared per scheme on `:root` (`src/index.css:42,150,186`) and is not one of the tokens a deck theme writes, so inside a themed deck the product's mark takes the *application's* ink or paper over a canvas the deck chose. Today's dot is drawn in the deck's own accent and therefore cannot miss; a mark held to the chrome's two values can.

Not in scope, and why: the amber `tone="warning"` mark on the waiting screen (`src/pages/ParticipantPage.tsx:522`), which is a state signal — the run has not started — rather than the product's mark, and which REQ167 deliberately left alone when it named the open-ring signet as a live run/ended state and recorded that as undecided. Also not here: the palette the house theme is drawn in, which is REQ168, and the organizer-logo behaviour of REQ136.
