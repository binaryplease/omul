## Description

As a presenter who has just put the join code on the projector and is now reading the link out to a room, I want that link to be the bare host and a path — `<host>/join/1234` — rather than a host with a prefix in front of it, so that the sentence I say out loud is one the room can hear once and type correctly; and as the operator of the deployment behind it, I want the app to sit on that same host beside a separate marketing site without either one claiming the other's paths.

## Notes

**What forces the shape.** The app was written as though it owned the whole of its origin: it answered `/` with its own home page, served its bundle from `/assets/`, and fell back to `index.html` for every path it did not recognise. All three are free while nothing else is on the host and all three are defects the moment something is. The marketing site is a separate build that wants `/` for its landing page and produces its own `assets/` directory, so the two collide in exactly the place a static handler cannot arbitrate.

**The asymmetry is the requirement, not a compromise.** What moves is the app's own front door; what stays is every path somebody is *sent* to.

- **Moved to `/app/`** — the home page, the two dialogs that open on it (`#create`, `#join`), and every built asset. Vite's `base` is `/app/`, so the HTML asks for `/app/assets/…` and `/app/brand/…`, and the collision with the site's `assets/` stops existing rather than being adjudicated.
- **Kept at the root** — `/join/*` first, because that link is spoken aloud and printed on the slide, and it is the whole reason for the arrangement. Then `/present/*`, `/preview/*`, `/results/*`, `/edit/*`, `/workspaces`, `/workspaces/*`, `/templates` and `/generate`: each of those is a link that has already been handed out or a page that exists *because* it is linkable, and a path that stops resolving breaks each of them in the same way. `/api/*` and `/ws` stay for the ordinary reason.
- **Not the app's at all** — `/`, and every other root path. The catch-all fallback is gone: a path the app does not own answers `404` rather than the app's home page, because on a shared host answering it is the app silently shadowing whatever the site put there.

**One exception, and it is for the deployment that has no site.** `/` answers a `302` to `/app/` rather than a `404`. On a shared host the proxy never routes `/` here, so the redirect is inert; on a standalone self-hosted instance there is nobody else to answer and the visitor typing the bare host is looking for the app. It is temporary rather than permanent: where the front door sits is a deployment's layout, not a fact to cache in a browser indefinitely.

**One descriptor, three readers.** `server/app-paths.ts` holds the base and the owned prefixes and nothing else — no dependencies, because the three things that must agree about them are on different sides of the build: `vite.config.ts` (the base stamped into asset URLs), `server/routes/static.ts` (which file, which fallback, which refusal) and `src/router.ts` (which page a URL is). A proxy in front derives its matcher from the same list; a matcher wider than it shadows a site page, and one narrower than it 404s a link the app hands out. The matching rule lives there too, so `/templates` is the app's and `/templates-for-teams` is not — a bare `startsWith` would take the second from a surface with no way to notice.

**What the move breaks if it is done by halves.** Every absolute URL the client builds pointing at `/` had to move with the home page, and they are not all in the router: the Better Auth callbacks for email verification, change-email and password reset all landed on `/?mode=…`, which after the split is the marketing site being handed a query parameter it has never heard of. They go through one `appHomeUrl()` helper now, for the reason there were four of them. The signet URL in `BrandMark` moved for the mirror-image reason: it is a string in the bundle rather than an attribute in the HTML, so the build cannot rebase it and it has to be spelled from the shared constant.

**Development had to keep matching production.** Setting Vite's `base` moves the dev server's whole surface under `/app/` and makes it answer `404` for everything outside it — including `/join/1234`, which would leave the one link this requirement exists for unopenable on the machine the change is written on. A dev-server middleware rewrites the root-owned pages onto the base internally, so Vite's own SPA fallback serves the same `index.html` production serves while the browser's URL — the only thing the client router reads — is untouched. It leaves `/api` and `/ws` alone: those belong to the dev proxy, and an HTML page is not an answer to either.

Out of scope: the reverse proxy, TLS, DNS and the machine configuration, none of which live in this repository and all of which are the operator's (docs/deployment.md §Running the image); the marketing site itself, which is a separate build in a separate repository; and `OMUL_BASE_HOST`, which is unchanged — still a bare host, still fatal if it carries a path.

Catalog note: written with `source: internal` because the business half was not in scope for this change and no business requirement number was available to cite. If one covers the host decision, the `source` line here is the thing to correct.

## Triage note

App home and built assets moved under `/app/`; `/join/*` and every other already-shareable link kept the host root; unowned root paths now 404 instead of falling back to the app. One descriptor in `server/app-paths.ts` read by the build, the static handler and the client router.
