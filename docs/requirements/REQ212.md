## Description

Opened over `http://<LAN-IP>:3000` — a non-localhost address without TLS, so the browser does not treat the page as a secure context — every page of the app renders instead of staying blank. That covers at least `/app`, `/join/<code>` and `/present/<id>`, in Chromium and WebKit.

Done when a test that runs the page's start-up with a `crypto` lacking `randomUUID` (as a non-secure context provides it) shows `/join/<code>` and `/present/<id>` rendering their content instead of throwing.

## Notes

**Current behaviour.** Found in the local acceptance run NST12404 (finding F17), reproduced three times (Chromium twice, WebKit once, plus `/app` once in Chromium) at 390 × 844 against a locally served build. The server answers HTTP 200 with the normal bundle, but the page stays white and `document.body.innerText` is empty. The console shows `TypeError: crypto.randomUUID is not a function`, and the React tree, which has no error boundary, unmounts. In that context `window.isSecureContext` is `false` and `crypto.randomUUID` is `undefined`, because browsers expose it only in a secure context (HTTPS or `localhost`). Over HTTPS and on `localhost` the fault does not occur.

**Where it is called today** (browser code only; `server/` and `cli/` run under Bun, where `randomUUID` is always present):

- `src/api.ts:1804-1811`: `getParticipantId` mints an id with `crypto.randomUUID()` when none is stored. It runs on first render of `src/pages/ParticipantPage.tsx:297` and `src/pages/PresenterPage.tsx:455`/`:460`, and when sending chat at `:724`. This is the throw the run recorded for `/join` and `/present`.
- `src/components/ui/Toast.tsx:25`: every toast.
- `src/store/editorDocument.ts:164-329` (slide and item factories), `src/components/SlideEditor.tsx:895-918`, `:1702-1705`, `:1763`, `:1814`, `:1870`, and `src/pages/WorkspacePage.tsx:296`: ids minted when editing.

The run did not trace which call blanks `/app`.

**Who is affected.** Anyone self-hosting omul on a LAN without TLS, and anyone testing a local server from a phone on the same network.

**Origin.** The fault is not a regression from recent work. The same `getParticipantId` with `crypto.randomUUID()` is already on `main`.

**Out of scope.** Serving omul over TLS on a LAN, and certificate set-up of any kind. Making secure-context-only APIs other than `randomUUID` work over plain HTTP (see the next note).

**Note.** The same run saw that `navigator.clipboard` is missing in this context too, so copy buttons cannot work there. A later record would have to decide how they behave. Separately, a presenter's QR code on `localhost` points at `localhost`, so a phone cannot follow it even after this record is done.
